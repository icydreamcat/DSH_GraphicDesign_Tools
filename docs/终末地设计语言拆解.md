## 0. 三十秒版本

**一句话公式**

> **纸面或炭面 + 四层深度 + 一格信号黄 + 等高线 + 技术制图底纹 + 极细线 + 巨型裁切字**

**三条主色**（终末地官网 CSS 全量统计）

| 角色 | 色值 | 出现次数 |
| --- | --- | --- |
| 墨 | `#191919` | **23（最高）** |
| 信号黄 | `#FFFA00` | **22（彩色中最高）** |
| 纸 | `#FFFFFF` | 19 |
| 墨的变体 | `#35373C` | 10 |
| 绿 | `#00FFA2` | 6 |
| 洋红 | `#FF1AAC` | 6 |

**四条被实测推翻或修正的说法**

| 流传的说法 | 实测结果 |
| --- | --- |
| ❌ "黄是柔和的暖调柠檬黄，不是高亮度荧光黄" | 官方主视觉成片黄 `#FFFC46`/`#FFFC27`，hue≈61、饱和度 0.91。**就是高亮度荧光黄** |
| ❌ "终末地风格 = 全直角" | 官方站用 `border-radius:50%`（8 处）、`2.625rem` 胶囊（3 处）；游戏内主菜单按钮是**圆角**浅色面板，动作按钮是**胶囊** |
| ❌ "终末地是深色科技风" | 游戏内**标题页、百科、商店都是白纸面**。正确的说法是"两种表面"（见第 2 节） |
| ⚠️ "游戏 UI 沿用官网的字号阶梯" | **不成立。** 实测：实测 28 / 30 / 68px，相邻比 1.07× 与 2.27×，**不构成比例阶梯** |
| ⚠️ **把截图的"合成值"读作"设计值"** | **截图是合成，不是平面。** 同一条状态胶囊在背景亮度相差 0.9 的条件下，填充只动 ≤7/255（→ **不透明**，实测 ≈`#2B2929`）；而主菜单四个**同款**按钮因一层**全局渐晕**读出 195→205（差 4%）。"不透明度"这类量在单帧里根本测不出来——详见 **9.2** |
| ⚠️ "四年 48% 完全未变" | **黑边污染。** 实机截图上下各 80px 纯 `#000000`（= 整帧 10.0%）。剔除后真实深色内容 **≈42%**，不是 48% |

## 1. 它要解决什么问题（先问功能，再问形式）

官方宣传语：**「跨越边境 直至前线」**

官方简介原文：玩家是**终末地工业**的**管理员**，在**塔卫二**这个"美丽却遍布危机"的世界，率领**干员**，用**源石发动机**与**集成工业系统**的自动化生产线，在荒野上建立并保卫人类的边疆。

三个必答项：

1. **可信的工业感。** 关键词不是"科幻"，是"工程"——要让人相信这套东西能运转、有编号、有规格。
2. **荒芜与生机并置。** 荒野无人区与自动化产线同时存在，画面里既有废墟也有草和花。
3. **高度秩序。** 界面要被读懂、被操作，信息必须能被排序。

**核心决策：它借用了「技术制图 / 工程文档 / 仪器面板」的语汇，而不是「赛博朋克」的霓虹语汇。**

这一条解释了后面所有选择。你会看到方格坐标纸而不是扫描线，看到仪表盘刻度而不是全息投影，看到测绘十字而不是故障艺术——**因为它们都是真实工程物上本来就有的东西。**

## 2. 核心结构：两种表面（比"品牌 vs 游戏"更准确的模型）

把设计语言分成"品牌传播层（白纸）"与"游戏内界面层（炭底）"是**两层模型，不成立**——因为**游戏内的标题页、终末地百科、商店都是白纸面**。正确的模型是**两种表面**（见第 2 节），与"品牌／游戏"无关。

正确的模型不是"在哪出现"，而是**这块表面要干什么**：

| | **纸面（明）** | **炭面（暗）** |
| --- | --- | --- |
| 游戏内实例（实测） | 标题页、终末地百科、商店 | 主界面表盘、战斗 HUD、背包、邮箱、任务、据点 |
| 游戏外实例 | 官网、主视觉、版本长图 | 深色加载页 |
| 底色实测 | `#E3E3E3` 纸（占 0.79 亮度档）· 标题页更亮至 0.83 | 近黑炭底（**≈42%** 像素落在最暗档，已剔除 10% 信箱黑边） |
| **面板层级** | 纸 + 印刷格线 + 极淡小三角水印 | **三层**：近黑底 → 深灰面板 **`#2B2929`**（实测）→ 浅色面板 **`#C3C3BF`–`#CDCBCB`**（实测） |
| 主文字 | 墨 `#191919` | 白 |
| 黄的角色 | **面**：满幅横带、大块平涂 | **信号**：数值、状态、发光路径、激活页签 |
| 底纹 | 印刷方格网 + 45° 斜线 + 斜排线填充 | 极细横向条纹 + 环形刻度 |
| 组织几何 | **直角坐标网格**（页面上真的印着格线） | **径向**（表盘） |
| 线宽 | **2px 略多于 1px**（2px 34.7% / 1px 27.5%） | **1px 绝对主导**（38%–55%） |
| 密度 | 极低（百科页最大区域占整帧 42.1%；标题页单一区域占**内容区** 95.9%） | 高（41–60 个独立区域） |
| 判据 | 需要**长时间阅读/浏览**的内容面 | 需要承载 **3D 场景**或**密集实时数据**的操作面 |

**为什么必须分开：**

- 纸面的任务是**被读懂、被记住**——它像一张印刷品，能一眼认出来，所以它敢留白。
- 炭面的任务是**被长时间注视**——3D 场景已经很花，界面必须退到后面，用炭底压住场景，只用黄色点出"现在要看的那个数"。

**关键的共同点（这才是设计语言的统一性所在）：两种表面用的是同一套记号。** 坐标十字、等高线、三角标记、拉丁微标签、等宽数字、`//` 前缀——纸面和炭面都在用。**变的是底色与密度，不变的是词汇表。**

**失败模式：** 把纸面的大块黄搬进炭面（得到 3D 场景上飘着一块黄色塑料板）；把炭面的仪表盘搬去纸面（得到一个需要凝视才能读懂、手机上完全坏掉的页面）。

### 2.1 修正：明暗语域不是"屏幕级"的二选一

上面那张表把两种表面写成了**屏幕级**的分类（这一屏是纸面，那一屏是炭面）。实机录像推翻了这个简化。

`HUD展示.mp4` 的探索 HUD 是一个**深色屏**，但其中 `进入俯瞰 [CAPSLOCK]` 提示胶囊实测是**近白 `#FDFCFC` 的不透明面板**：

```
逐通道 alpha  R=1.000  G=0.999  B=0.999      (背景激励 16.8%，52 帧)
方差比 0.002–0.006  →  alpha ≥ 0.997  →  OPAQUE
```

**暗屏内部可以承载一个明语域的元件。** 而且它出现的规律是功能性的——**屏幕上最亮的那一个元件，就是此刻唯一的焦点提示**。焦点靠**反相**拿到，不靠加粗、不靠换色。

> **修正后的模型：语域属于元件，不属于屏幕。**
> 一屏之内可以同时存在：近黑底 → `#2B2929` 深面板 → 浅色磨砂面板 → 一个近白元件。判断某个元件该用哪个语域，看它在信息层级里的位置——**最上面那一级可以用反相换取最强注意力，代价是它一次只能有一个。**

## 3. 色彩系统

### 3.1 三个主色，一条纪律

```
纸  #FFFFFF / #E3E3E3     墨  #191919     信号黄  #FFFA00
```

纪律只有一条，但它解释整套配色：**黄是信号，不是色块。**

在炭面上，黄色承担**信息负载**——数值、状态、激活页签、物的流向。最有力的实例是工厂系统：**传送带的路径是用发光的黄色细线画在草地上的**（官方实机画面），玩家靠这条黄线读产线。**黄色在这里的面积由逻辑决定，而不是由构图决定。**

### 3.2 黄色的家族（一条轴，不是一个值）

官方 CSS 里同时存在 6 个黄：

| 值 | 用途 |
| --- | --- |
| `#FFFA00` | 主信号色 |
| `#FFF500` / `#FFFC46` / `#FFFC27` | 主视觉成片黄（受插画混色影响略有偏移） |
| `#FFF000` | 实心填充 |
| `#FFFF21` | 高亮 / 悬停 |
| `#EFE701` | 悬停加深 |
| `#E6DE01` | 按下加深 |

**规律：越深的值用在越"被按下"的状态上。** 黄色在亮底上做文字会直接消失，所以亮底必须换深档（实测 1.07:1，等于抹除）。

### 3.3 另外三个颜色：橙、红、绿

这一层常被遗漏。实机截图给出了三个与黄明确分工的颜色：

| 值 | 实测出现处 | 推断角色 | 置信度 |
| --- | --- | --- | --- |
| **橙** `#FF7500` / `#DB7722` | 百科页的六颗菱形徽标（该屏**唯一**彩色，占 0.104%）；主菜单按钮角标；标题页最饱和像素 | **新 / 未读 / 待处理标记** | 中高 |
| **红** `#840000` 系 | 主菜单 `BREAKING NEWS` 标签；玩家卡 `满级` 徽标 | **紧急 / 状态徽标** | 中 |
| **绿** `#00FFA2` | 官方 CSS（6 次）；实机中的黄绿辉光 | 能量 / 正常状态 | 低-中 |
| 洋红 `#FF1AAC` | 官方 CSS（6 次）；实机天空的异常现象 | 异常 / 侵蚀 | 低-中 |

**读法：黄是唯一的品牌信号色；橙是"待处理"标记色；红是"紧急"标记色。** 三者不可互换——仿制时把它们混用是常见错误。

### 3.4 强调色预算（本拆解最需要精确的一个数）

我在**五个界面**上测了同一组指标。两个指标必须分开读：

- `flatShare` — 属于**未被中断的大面积平涂**的彩色像素。**它测的是"平涂存活量"，不是"设计的强调色面积"**——标题页那条满幅黄带，`flatShare` 只有 1.0%，而它的色相簇是 4.55%，因为带被字标、灰块和辉光打断了
- **色相簇占比** — 该色相的全部像素，含细线、发光线、小徽标

| 界面 | `flatShare` | 黄色相簇 | 备注 |
| --- | --- | --- | --- |
| 官方 PC 主视觉 | **1.2%** | 3.3%（hue 61） | 大面积黄几何块 |
| **标题页** | **1.0%** | **4.55%**（hue 57） | 满幅黄带，但被字标/灰块/细纹打断 |
| **主界面表盘** | **1.9%** | 5.5%（hue 53） | 激活页签 + 环弧 + 高亮区域 |
| **战斗 HUD** | **0** | 3.1%（hue 47） | 黄以**自发光辉光**形式存在，无平涂 |
| **终末地百科（纸面）** | **0** | 0 | 唯一彩色是橙色徽标 0.104% |
| **产线／蓝图视图**（录像实测） | **3.1%** | 4.8%（hue 54 `#ACA457` 1.85%，hue 34/25 橙黄合计 5.5%） | **全篇最高**——因为黄本身就是这张图的内容；`#F8EB6D` 0.46% |

**结论（可执行）：**

> **平涂强调色 0%–2%，唯一的特例是产线蓝图视图的 3.1%；色相存在感 3%–5.5%；战斗与阅读屏趋近 0。**
> "强调色占 1%–5%"这个区间过于含糊，不可用作判据。正确的读法是：**大块平涂绝不超过 2%**，而"看见的黄"主要是**线、发光和小徽标**累积到 3%–5%。

**方法论警告（重要）：** 战斗屏 `flatShare` = 0 **不代表没有黄色**。那一屏的黄色是发射光，边缘柔和，不构成平涂区域，**该指标读不出它**。**在自发光为主的界面上，`flatShare` 会系统性低估**，必须同时看色相簇。同理，纸面上那条"满幅黄带"在 x=1150 处的合成色是 (210,213,90)——R−G 从纯纸面区的 **+8** 翻到 **−5**，说明人物边缘有辉光/扩散层在渗。**连一条画在白纸上的实心黄带都不是平面。**

### 3.5 实机五金配色（游戏内物体）

```
白色复合箱体  +  黑色底盘  +  黄绿警示条  +  极小号拉丁文贴标
```

- 设备主体是**哑光白/浅灰面板**，不是金属银
- 底盘与框架是**接近纯黑的炭色**，制造重量感
- 黄以三种形式出现：**斜向危险条纹**、机器侧身**长条色带**、**发光地面管线**
- 贴标是**极小号全大写拉丁文**（`ENDFIELD`、`CLASS 4 ERROR DISCONNECT`、`NODE CASCADE SYSTEM`），小到几乎不可读——它的功能是**纹理**，不是信息

### 3.6 与《明日方舟》的对照（同方法实测）

| | 明日方舟官网 CSS | 终末地官网 CSS |
| --- | --- | --- |
| 统计字符 | 152,714 | 130,777 |
| 最高频色 | `#000` ×**89** | `#191919` ×**23** |
| 第二 | `#fff` ×81 | `#fffa00` ×22 |
| 第三 | `#18D1FF` 青 ×**42** | `#fff` ×19 |
| 强调色相 | **青** | **黄** |
| 灰阶倾向 | 中性灰 | 冷偏蓝（`#35373C`、`#1F1F22`） |

**两条断裂：** 强调色从青换成黄；底色从纯黑纯白退到 `#191919`（一款带一点温度、避免"死黑"的炭色）。
**一条继承：** 两者都是**单强调色 + 中性灰阶**的纪律，绝不铺开多色。

## 4. 排版系统

### 4.1 拉丁展示字：Novecento Sans Wide（家族 DNA）

**证据最硬的一条，因为它被两个完全独立的来源指向同一结论。**

来源一 —— 明日方舟官网 CSS 声明的字族（解压后实测）：

```
font-family: Novecentosanswide-UltraBold / -Bold / -DemiBold / -Medium
font-family: Bender-Bold / Bender-Regular
font-family: Oswald-DemiBold / Oswald-Medium
font-family: SourceHanSans-Bold
```

来源二 —— 社区版「终末地白色大字生成器」内嵌的字体文件：

```
EndfieldByButan.ttf            ← 专门的终末地面（社区还原，非官方）
NovecentoWideUltraBold.otf     ← 拉丁
NotoSansHans-Black.otf         ← 中文
```

**两个来源都落到 `Novecento ... Wide ... UltraBold`。**

| 属性 | 规格 |
| --- | --- |
| 字面 | **宽体（Wide）**——字腔宽、字面方 |
| 字重 | **UltraBold / Black（900）** |
| 大小写 | **全大写** |
| 用途 | 巨幅展示字、机器贴标、区块标题 |

**注意它与"窄体科技感"的常见做法相反：终末地用的是宽体。** 窄体读成"仪表读数"，宽体读成"钣金喷漆/工程标牌"——后者才是工业感的来源。

**授权提醒：** Novecento Sans Wide 是**商业字体**（Jan Tonellato / Synthview）。做替代时用其他**宽体超粗**拉丁字即可，**不要分发 Novecento 文件**。思源黑体 / Noto Sans CJK 是 SIL OFL，可自由商用。

### 4.2 中文：思源黑体 / Noto Sans CJK

- 明日方舟官网中文：`SourceHanSans-Bold`
- 终末地巨幅大字中文：`NotoSansHans-Black`

思源黑体与 Noto Sans CJK 是同一款字在两个发布方下的名字。**两个 IP 的中文侧是同一款字，只是字重不同**；终末地的展示字用 **Black（900）**——常规字重压不住宽体拉丁。

游戏内正文实测（见 4.4）是**常规/中等字重**，不是 Black。Black 只留给展示层。

### 4.3 官方站的字阶（网页层）

根字号 16px，rem 制。终末地官网 `font-size` 频次：

| rem | px | 频次 |
| --- | --- | --- |
| `1.25rem` | 20 | **12（最高）** |
| `1.5rem` | 24 | 7 |
| `2rem` | 32 | 6 |
| `2.5rem` | 40 | 5 |
| `2.25rem` | 36 | 5 |
| `1.875rem` | 30 | 4 |
| `1rem` | 16 | 4 |
| `3rem` | 48 | 3 |

主簇落在 **20 / 24 / 32 / 40 / 48**，相邻主级约 **×1.25**——**以 16px 为基、比例 1.25 的实用型阶梯**。

对照明日方舟官网：`.875rem`(14) ×31、`1.25rem`(20) ×29、`1.125rem`(18) ×20、**`7rem`(112) ×10**。**说明"巨型展示字"在这家公司的 DNA 里早就存在。**

### 4.4 游戏内的字阶（实机实测 —— 与网页层不同）

用逐行墨量扫描在 2560×1600 原生截图上实测：

| 层级 | 样本 | 墨迹高度 | 推算字号 |
| --- | --- | --- | --- |
| **展示数字** | 主界面 `07`（探索等级） | **49px**（数字高） | **≈68px** |
| **按钮标签** | 主菜单 `干员` | **26px** | **≈30px** |
| **正文** | 邮箱正文 | **25px** | **≈28px** |

**相邻比例：28 → 30 是 1.07×；30 → 68 是 2.27×。**

> **结论：游戏内 UI 不使用连续的比例阶梯。** 它用**一段很窄的文本带（28–30px）+ 一次大幅跳升的展示层（≈68px）**构成层级。
> 这与官网那套 1.25 阶梯是两回事。**"两者一致"的假设不成立，实测已否定。**

（推算字号依赖"CJK 字面占 em 约 0.88、数字高约 0.72em"的经验比，标为约值。像素高度是实测。）

### 4.5 行长与行距（实测）

| 指标 | 实测值 | 评价 |
| --- | --- | --- |
| 邮箱正文**行长** | **1285px** | 按 28px 字号计 ≈ **46 个汉字/行** |
| 行/段间距 | **76px**（≈2.7× 字号） | 三行等距 |

**46 字/行已经超出中文舒适区（25–40）的上沿。** 这是一个真实的设计取舍：宽屏邮箱面板优先填满宽度，代价是回扫距离偏长。若要仿制，建议收到 36–40 字/行。

行距 76px 我无法完全区分"行距"与"段距"——三行都是独立短句且都不换行。**但 76px 作为"文本行间距"读是安全的。**

### 4.6 三类文字角色（照做就能对）

| 角色 | 字面 | 字重 | 大小写 | 字距 | 用途 |
| --- | --- | --- | --- | --- | --- |
| **展示字** | 宽体 | UltraBold / Black | 全大写（拉丁） | 略开 | 巨型标题、机器贴标、KV 大字、巨型幽灵数字 |
| **正文** | 常规 | Regular / Medium | 句首大写 | 0 | 说明、邮件、规则 |
| **技术标注** | 等宽 or 常规 | Regular | **全大写** | **+0.10 ~ +0.20 em** | 编号、坐标、版本号、`ENDFIELD` 署名 |

**第三行是"技术味"的主要来源**，而实机把它用到了极致——见 5.7 的拉丁微标签。

### 4.7 数字

数字要**等宽（tabular numerals / `tnum`）**：遥测数值跳动时不能横向抖动。实机里的读数（`2406`、`1896.40`、`6435 /9800`）都具备这个特征。

实机还给出一个可复用的**数值排版对**：

```
6435 /9800      →  主值大、白色    上限小、灰色    斜杠分隔
100 %           →  百分比后留一个空格再接 %
```

## 5. 形态语言：图形的词汇表

每条注明**功能**。没有功能的图形在这套语言里不该存在。

### 5.1 等高线（核心母题）

**识别度最高的一个图形。** 四个独立来源指向它：

1. 官方品牌标识：细线倒三角内填充**等高线地形纹理**
2. 2022 技术测试主界面：**表盘正中心就是等高线地形图**
3. 2026 主界面：区域地图为灰白地块 + 斜排线填充，背景仍是细密等高线
4. 标题页底部：`MOUNTAIN CONTOUR` 压着 `峰形山`——**等高线直接作为地名标注出现**
5. 百科页底部：柔和的山影轮廓

**功能：** 表示"地形 / 未测绘的疆域 / 探索"，也就是核心玩法。**它不是装饰——它是地图。**

**用法：** 作底纹时对比度压到 **1.06–1.6:1**；作主体时可高对比；线宽**一律发丝级**。

### 5.2 技术制图底纹

1:1 切开官方主视觉与百科页看到的实际构成：

- **极细几何格网**：方格之上再叠 45° 斜线
- **斜排线填充块**：细密平行斜线填满的区块（工程制图的剖面记号）——实机上用于**区域地图的陆地填色**
- **点划线中心线**：百科页面上有明显的 dash-dot 中心线
- **散落的极淡小三角水印**

**实测规格：**

| 指标 | 值 |
| --- | --- |
| 官方主视觉方格节距 | **117px @1600px 宽 = 画布宽 7.3%** |
| 百科页纸面方格节距 | **≈125px @2560px 宽 = 4.9%**（目视读数，见下方警告） |
| 纸面网格对比度 | **≈1.06:1**（区域 `impliedOpacity` 0.09–0.10） |
| 标题页**横向细纹**周期 | **14px @1600px 分析尺度（≈原生 22px）**，`rowStrength` **0.915**，线占比 14.6% |

> **一格额外的纹理发现：** 标题页检测到一条**强度 0.915 的横向线结构**——这是五屏里最强的周期性信号（作为对比，各屏列方向强度普遍为 0）。周期换算到原生约 22px。它对应纸面上那层肉眼可见的细密横纹。**读法：纸面不是纯色，它有一层约 1.4% 画布高的横向纹理。** 需要注意这条信号也可能是编码/抖动产物，我标为中等置信度。

> **方法论警告：** 纸面网格的对比度**低于检测阈值**（列峰仅 0.0167），所以 `columnPitch` 报 null 是正常结果，125px 是目视读数而非测值。我已在第 9 节标注。

**最关键的一条：底纹必须局部出现，不能均匀铺满。** 官方主视觉的空间细节分布：中部峰值 **0.079**，底部两角 **0.010**——相差近 8 倍。均匀铺满会读成"壁纸"，局部出现才读成"制图"。

### 5.3 切角、圆角与圆形（实测，纠正误传）

| 场合 | 实测形态 |
| --- | --- |
| 官方站 | `50%`（8 处）、`2.625rem` 胶囊（3 处）、`.25rem`（3 处） |
| 游戏内主菜单按钮 | **圆角浅色磨砂面板**（约 12–16px 圆角）+ 1px 内高光边 |
| 游戏内动作按钮（邮箱） | **胶囊** |
| 游戏内状态/关闭按钮 | **圆形** |
| 实机设备 | **硬边 + 局部切角（chamfer）**——钣金件的真实处理方式 |

**结论：正确的规则不是"全直角"，而是——形状由物体的性质决定。** 一个点在物理上是圆的就画成圆；一块面板是钣金就画成直角。**不要为了风格统一把圆点画成方块，也不要为了柔和把面板倒圆角。**

### 5.4 发丝线（实测，五个界面的横截面）

| 界面 | 1px | 2px | 3px | 中位线宽 |
| --- | --- | --- | --- | --- |
| **标题页（纸）** | **54.8%** | 27.7% | 9.1% | **1** |
| 战斗 HUD（炭） | **49.0%** | 28.7% | 10.6% | 2 |
| 主界面表盘（炭） | **45.4%** | 29.3% | 10.9% | 2 |
| 背包（炭） | 38.2% | 30.4% | 11.9% | 2 |
| **终末地百科（纸）** | 27.5% | **34.7%** | 23.2% | 2 |

**最重要的发现在最后两行：纸面上的线更重（2px > 1px），炭面上的线更细（1px 主导）。**

这有物理理由：**在近黑底上，1px 亮线已经足够可见；在亮纸面上，1px 会消失，必须加到 2px。** 同一条规则不能跨表面照搬。

> **口径警告：这张表不是干净的对照。** 纸面各屏**没有 3D 背景**，笔画统计几乎纯是 UI；战斗 HUD 那屏画面主体是场景，1px 占比里混着场景边缘、辉光细丝和后期锐化。**"标题页 54.8% vs 战斗 49.0%"不能读作"两套 UI 的线宽不同"。** 要干净地比较，只能在 UI-only 区域内测量（裁掉场景或加遮罩）。

**规则：炭面分隔、框、刻度、网格一律 1px；纸面提升到 2px。需要强调时不要加粗单线，而是加线或换颜色。**

### 5.5 标记与指针（按功能分类）

| 记号 | 类型 | 功能 | 实测特征 |
| --- | --- | --- | --- |
| **坐标十字 + 编号** | 标记 | 定位 / 测绘感 | `＋ AP04`、`＋ AP06`；十字极小，编号四字符，灰色 |
| **橙色菱形徽标** | 标记 | 新 / 未读 | 旋转 45° 方形，带 **1px 内描边**，约 34–40px |
| **黄色描边三角** | 指针 | 当前项 / 方向 | 空心，描边约 2px，落在表盘环上 |
| **白色十字** | 标记 | 定位 | 极小，`＋` |
| **拉丁微标签** | 标注 | 技术语气 | **压在中文名上方**，全大写小号：`MAILBOX`/`邮箱`、`MOUNTAIN CONTOUR`/`峰形山` |
| **`//` 前缀** | 记号 | 路径 / 层级感 | `// 邮箱` |
| **`-` 前缀** | 记号 | 条目前缀 | `- 收件箱` |
| **巨型幽灵数字** | 面 | 承担构图 | `01`–`06`，字高约 **135px**，极淡灰 |
| **引号水印** | 面 | 装饰字形 | 极大、极淡（邮箱页背景） |
| **虚线分隔** | 线 | 轻量分隔 | `- - - -`，不是实线 |
| **满幅黄带** | 面 | 构图主梁 | 标题页，贯满整个宽度，字标压在它上面 |

**使用纪律：** 标记（无方向的符号）价值在**位置**；指针（有头有尾）价值在**路径**。所有记号必须远小于字标——**尺寸比控制在 1:7 或更小**，否则它们变成小竞争对手。

### 5.6 图元的生成规则（重要）

百科页的六个图元（教学记录 / 威胁图鉴 / 武器图鉴 / 装备图鉴 / 设备图鉴 / 物品图鉴）不是插画，是**几何拼装**：

> **规则：每个图元由矩形、圆、菱形三种基元拼成，且基元的角点、圆心落在方格网的交点上。**

这条规则解释了为什么它们看起来"像工程符号而不像图标"。**这是一条生成规则，不是一百次手工摆放**——照做时先定网格，再把圆/方/菱吸附到交点上。

### 5.7 炭面的界面构成（纠正"深色 UI"的印象）

主界面表盘的实测构成**不是**"深色界面"，而是：

> **近黑底 + 大量浅色磨砂面板**

- 底色：**≈42%** 像素落在最暗档（整帧 48.0%，其中 10% 是信箱黑边）
- 左侧四个大按钮 + 右侧十个较小按钮，**全部是浅色（亮度 0.33–0.47）磨砂面板**，沿表盘弧线排布
- 面板上：**黑色实心图元**（由方/菱/圆带 45° 切角拼成）+ 下方中文标签
- 选中态用**反相**（浅底深字），不是加边框
- 列表行靠**1px 亮边**分隔，行间露出更暗的底

**这解释了为什么它既"暗"又不压抑：暗的是底，亮的是按钮。**

### 5.8 常驻遥测

每一屏左下角都有同一行极小灰字：

```
42ms   UID: 1420715534        （各屏耗时为 42/63/165ms）
```

标题页左下有 `CN_WIN_REL_1.5.3_C9577065_E9539288`。

**功能：** 它不服务于玩家，它服务于"这是一个被监控的系统"的世界观。**它是这套语言里最便宜、最有效的一个记号——四五个字符的等宽灰字，立刻把界面从"应用"变成"设备"。**

### 5.10 世界自带信号色（这是整套配色最聪明的一处）

`HUD展示.mp4` 的野地画面里，**前景铺满黄色野花**（`mostChromatic` `#FFCD57`，hue 42）。同一段录像里还有：黄色滑索线、黄色环形交互标记；官方实机画面里有黄色危险斜条纹与发光的产线路径。

**UI 的信号黄不是外来的。** 它与世界里的花、产线的辉光、设备的警示条属于同一个色相家族。

**因此它在画面上从不显得"贴上去"。** 界面上的黄读起来像"从这个世界里取来的信号"，而不是一层外来图层——这正是绝大多数仿制失败的地方：它们从色板里挑一个高饱和黄刷到界面上，得到一块塑料板。

> **可执行：先在世界美术里确立信号色，再让 UI 使用它。** 不是先定 UI 主色，然后去世界里找补。

### 5.11 分层：这套语言的深度轴（本文框架的一次修正）

**这一节否掉的不是一个数字，是本文前几版的一个维度。**

我原先的分析框架是二维的：面积占比、元素数量、线宽分布、对比度、留白比例——全是平面上的量。**它没有深度轴。** 后果很具体：我在 6.1 节写"大块也是淡的"（隐含不透明度 0.329–0.457），并据此在 §8 定了"元素要多、要淡"。

**但那个"淡"不是设计决策，是四层叠合后的合成结果。** 我把一个**堆叠结构**读成了平面上的**低对比决策**。

#### 实测到的深度结构

| 层 | 实测 | 职务 |
| --- | --- | --- |
| 底 | 近黑（≈42% 像素落在最暗档） | 压住 3D 场景，让界面退后 |
| 面板 1 | **`#2B2929`** | 承载列表与实时数据（状态胶囊） |
| 面板 2 | **`#C3C3BF`–`#CDCBCB`** | 可操作面（主菜单按钮） |
| 顶层 | **`#FDFCFC`** | **焦点，反相，且只能有一个** |

#### 三条由此成立的规则

**1. "高频低对比"是被分层供养的，不是单独成立的。**
在一个平面上撒一百个 6% 的记号是糊；把它们分布到四个深度层上才读成系统。**"要淡"这条处方是不完整的——它给了密度，没给结构。**

**2. 焦点靠反相拿到，不靠加粗、放大或提高对比。**
`HUD展示.mp4` 里那条 `#FDFCFC` 提示胶囊既不是最大的，也不是对比最高的；它是**唯一翻转语域**的那一个。这比加边框、投影、放大都便宜得多。代价明确：**一次只能用一个**，用第二个就没有反相可言。

**3. 分层 ≠ 半透明。**
两条胶囊实测都是 **OPAQUE**（α ≥ 0.942 / α ≥ 0.997）。**该保证可读性的地方，它拒绝让世界透过来**——这与当下流行的毛玻璃方向相反，而且是个可测的取舍：用"失去世界感"换"阅读稳定"。

#### 代价（必须写下来）

**分层是屏幕原生手法，印刷与单色下会崩。** `#2B2929` 压在近黑底上实测对比度仅 **1.144:1**——它的"可见"完全依赖底可控。一旦打印、转灰度，或遇到不分离这些明度的读者，这一层信息就消失。

这与 5.4 节"纸面线更重（2px）、炭面线更细（1px）"是同一个物理原因。由此上升成的原则：

> **凡是靠明度差建立的结构，都要问一句"它在灰度下还剩多少"。** 靠形状、位置、字号建立的结构能活过打印；靠明度差建立的结构不一定。

#### 尚未建立的部分

- **完整的 z 轴顺序**：那四层是"一套基底的提亮档"，还是四个独立 token？未测。
- **浅色面板是否半透明**：仍卡在"主菜单背景静止、无激励"上（见 9.2）。

## 6. 版式与网格（实测）

### 6.1 2022 → 2026：主界面表盘四年对照

我原有一张 2022 技术测试的主界面截图（500×281）。现在有了 2026 版的同一界面（2560×1600）。**同一套测量，四年对照：**

| 指标 | 2022 技术测试 | 2026 当前版本 | 判断 |
| --- | --- | --- | --- |
| 最暗档像素占比（整帧） | 48.1% | 48.0% | ⚠️ 看起来一致，其实是巧合 |
| ↑ 剔除信箱黑边后的**真实深色内容** | 48.1%（16:9 裁图，无黑边） | **≈42.2%** | 差约 **6 个百分点** |
| 信箱黑边 | 无 | **上下各 80px 纯 `#000000` = 整帧 10.0%** | 实机截图固有，污染所有整帧统计 |
| 1px 细线占比 | 40.5% | **45.4%** | 更细了 |
| 独立区域数 | 56 | 41 | 同量级 |
| 最大单一区域占比 | 14.2% | **8.6%** | 更分散 |
| 顶部大块的"隐含不透明度" | 0.381 | 0.329 / 0.457 / 0.438 | ⚠️ 只能读作**合成后的有效亮度覆盖**，不能读作设计不透明度（见 9.2） |
| 列网格节距 | null | null | 见 6.2 警告 |
| 设计性平涂强调色 | — | **1.9%** | 口径见 3.4 |

**修正后的结论：** 纪律稳定，但"一个字没变"的说法不成立。按剔除黑边的数字读：**最暗档从 48.1% 降到约 42%**，细线占比从 40.5% 升到 45.4%，最大区域从 14.2% 降到 8.6%——**底更少了，线更细了，元素更散了。**

### 6.2 关于"无列网格"这个方法论纠正

检测器在**主界面**报 `columnPitch: null`。据此得出"组织几何是径向的"——**结论是对的**（目视可确认那个表盘），**证据用错了**：

> **在背包页（一个视觉上明确的规则网格）上，检测器同样报 `null`。**

原因：检测器找的是**"画出来的线"的周期性**，不是**"平铺的格子"的重复**。背包是瓦片式方格，没有画出的格线；百科页有画出的格线但对比度只有 1.06:1，低于阈值。

**所以 `columnPitch: null` 只能读作"未检出"，绝不能当作"不存在"的证据。** 把它当证据用，是一个已修正的误读。

可靠的替代判据：**看画面上有没有画出来的格线**，以及**元素是否围绕一个圆心排布**。

### 6.3 两种表面的版式规则

| | 纸面 | 炭面 |
| --- | --- | --- |
| 组织几何 | 直角坐标网格（页面上印着格线 + 刻度尺 + 四角对位方括号） | **径向**（表盘圆心 + 环状刻度 + 弧形排列的按钮） |
| 网格作用 | **生成规则**：图元角点吸附到交点 | 无网格，靠圆心距离分层 |
| 留白 | 极大（标题页 86.3% 是单一区域；百科页 42.1%） | 极小（41–60 个区域） |
| 焦点 | 单一（字标 / 六格索引） | 单一（盘心） |

**可执行：** 做**阅读型**版面用列网格并把网格画出来；做**仪表型**界面用径向，让所有元素围绕一个圆心。**不要给径向构图硬套列网格。**

### 6.4 官方长图的版式（当前版本，772×9999）

长图是终末地对外传播的主力版式。1:1 切开的实际系统：

1. **满版黄底 KV**：人物全彩压在高饱和黄上；右上角标准字（`明日方舟` 小 / `终末地` 大，2×2 堆叠，黑字白牌）；右下角**巨型白色描边字母被画布边缘切断**
2. **过渡**：黄与白之间用细密**斜排线**过渡，不是硬切
3. **小节标题**：黑体粗中文 + 左侧**实心三角标记**
4. **分区锚点**：**黄色横带**，右端放小号 `ENDFIELD` 署名
5. **字段区**：**左列黑牌标签**（`#191919` 底白字小方块，`活动时间` `活动说明`）+ 右列正文
6. **关键词**：用**【】**括起并加重字重（`【贴纸·开拓节美食】【嵌珠玉】`）
7. **分隔**：1px 发丝线
8. **数字**：等宽 `2026/03/29 12:00 - 2026/04/19 04:00`，后跟较轻的 `(服务器时间)`

## 7. 继承与断裂（实测对照）

| 维度 | 明日方舟 | 终末地 | 判断 |
| --- | --- | --- | --- |
| 拉丁展示字 | Novecento Sans Wide UltraBold | Novecento Wide UltraBold | **继承** |
| 中文 | Source Han Sans Bold | Noto Sans Hans Black（展示层） | **继承**（同款字，字重更重） |
| 强调色 | 青 `#18D1FF`（×42） | 黄 `#FFFA00`（×22） | **断裂** |
| 底色 | 纯黑纯白 `#000`×89 / `#fff`×81 | `#191919`×23 / `#fff`×19 | **断裂**（退离纯黑） |
| 灰阶 | 中性灰 | 冷偏蓝（`#35373C`） | **断裂** |
| 纪律 | 单强调色 + 中性灰阶 | 单强调色 + 中性灰阶 | **继承** |
| 巨型字 | 有（`7rem`×10） | 有（KV / 长图 / 标题页 / 幽灵数字） | **继承** |

## 8. 可执行规则：做一套「终末地风格」

### 第一步：定表面

1. **先决定这块表面是纸面还是炭面**，判据是功能：需要长时间阅读 → 纸面；要压住 3D 场景或承载密集实时数据 → 炭面。**不要混。**
2. **纸面底用 `#E3E3E3`，不用纯白**（纯白读成屏幕，浅灰读成纸）。炭面底用近黑，**不用纯黑**，墨用 `#191919`。
3. **两种表面可以在同一个产品里共存**——这正是终末地的做法。但每一屏只能是一种。

### 第二步：定强调色

4. **主信号色只选一个黄：`#FFFA00`。** 加深沿轴走 `#FFF000` → `#EFE701` → `#E6DE01`。
5. **大块平涂黄 ≤ 2%**（实测 0–1.9%）；**色相总存在感 3%–5.5%**。超过 5% 它就从"信号"变成"底色"。
6. **橙 `#FF7500` 只用于"新/未读/待处理"标记，红 `#840000` 系只用于紧急徽标。** 不要用黄做这件事，也不要把三者混用。
7. **黄在亮底上不能做小字**（1.07:1，等于抹除）。亮底需要黄字时换深档（如 `#6B5D00`）。

### 第三步：定字

8. **展示字：宽体 + UltraBold/Black + 全大写。** 中文用**思源黑体 / Noto Sans CJK 的 Black（900）**（免费可商用）。拉丁找一款**宽体超粗**替代 Novecento（**商业字体，注意授权**）。
9. **游戏/界面层不要照搬网页的 1.25 阶梯。** 实测的做法是：**文本带 28–30px + 展示层约 68px**（相邻比 1.07× 与 2.27×）。要的是"窄文本带 + 一次大跳升"，不是多级细阶梯。
10. **网页/传播层**才用 16 基、比例 1.25 的阶梯：16 / 20 / 24 / 32 / 40 / 48。
11. **正文行长收到 36–40 汉字/行**（实测 46 偏长）。行距按 1.7–2.0em 起，段间距再叠 1em。
12. **技术标注：小号 + 全大写 + 字距 +0.10~0.20em**，并**压在中文名上方**——这是最省力的"技术味"来源。
13. **数值全部等宽（`tnum`）**；用"主值大 + 上限小灰 + 斜杠"的排版对。

### 第四步：定图形

14. **线宽分表面：炭面 1px，纸面 2px。** 需要强调就加线或换色，**不加粗**。
15. **底纹用方格网 + 45° 斜线 + 斜排线填充块**，模数取画布宽的 **5%–7%**（实测 4.9% 与 7.3%）。**必须局部出现、局部消失**，不能均匀铺满。其对比度压在 **1.06–1.6:1**。
16. **加等高线**，并让它有功能：做区域填色、做地名标注、做盘心地图。不要只当纹理。
17. **图元用生成规则**：由矩形/圆/菱形拼装，角点吸附到方格交点。
18. **把测绘记号用起来**：`＋` 十字 + 四字符编号，散落在空处；四角放对位方括号；边上放刻度尺。
19. **常驻一行极小等宽遥测**（`42ms  UID: 0000000000`）——这是把"应用"变成"设备"的最便宜手段。
20. **元素要多、要淡——但"淡"必须由分层供养。** 目标：**40 个以上区域，单个最大 ≤15%**。平面上撒一百个 6% 的记号是糊；把它们分到 3–4 个深度层上才读成系统。所以先定层，再定密度（见 5.11）。
21. **形状跟着物体的性质走。** 面板圆角≤16px 或直角，动作按钮可胶囊，点和头像才用正圆。

### 第五步：定深度

**这一步是我原先框架里缺失的那一维。** 前面所有量都是平面上的（面积、数量、线宽、对比度），深度不是。定完图形之后、定版式之前，先把层定下来。

22. **定层：底 → 承载面 → 可操作面 → 焦点层，共 3–4 层，每层一种职务。** 炭面实测四档：近黑底 → `#2B2929` → `#C3C3BF`–`#CDCBCB` → `#FDFCFC`。
23. **焦点层用反相，不用加粗/放大/加边框，且一次只留一个。** 这是全套语言里最便宜、也最容易用滥的手法。
24. **该不透明就不透明。** 分层不等于半透明。终末地的两条 HUD 胶囊实测都是不透明的（α ≥ 0.94 / 0.997）——需要读的数据不让底透过来。
25. **每定一个色值，同时写下它落在哪个面上。** 同一个色在不同层上需要不同的取值（亮底上的黄必须换深档，1.07:1 等于抹除）。**底色归一套、文字归另一套，就是裂缝。**
26. **靠明度差建立的结构要过一遍灰度检查。** 1.144:1 的面板在屏幕上成立，在打印和单色下消失。

### 第六步：定版式

27. **阅读型版面用列网格**（并把格线画出来）；**仪表型界面用径向**。不要互换。
28. **长图版式照搬**：黄带分区 → 黑牌字段名 → 三角条目 → 发丝线分隔 → 【】关键词 → 等宽数值。

### 第七步：禁止清单

29. ❌ 把纸面的大块黄搬进炭面（或反之）
30. ❌ 同时铺开黄、青、绿、洋红、橙——**它们分属不同表面/不同状态，不是一套配色**
31. ❌ 随机六边形、扫描线、故障效果、霓虹渐变、密集 HUD 装饰
32. ❌ 为了"更有科技感"而编造协议名、系统代号、加载计量条
33. ❌ 用 `columnPitch: null` 之类的"未检出"当作"不存在"的证据
34. ❌ 复制官方 logo、角色立绘、UI 截图
35. ❌ 分发 Novecento 字体文件（商业授权）
36. ❌ **只按平面读数下判断。** 一个"很淡"的元素可能只是一个叠在深底上的浅色面板——那是结构，不是克制（见 5.11）

### 9.2 分层效应：单帧测量的边界（方法论）

**一张截图不是平面，是一次合成。** 把整帧当作"平面的比例对照"来读，会把若干**合成值**当成**设计值**。本节把它拆开，并给每一类分层配一个判据。

| 分层机制 | 为什么破坏平面测量 | 污染的指标 | 判据 |
| --- | --- | --- | --- |
| **① 半透明合成** | 读数 = α·元件 + (1−α)·背景。**"中灰不透明面板"与"深底上的半透明白面板"在单帧里无法区分** | 一切"不透明度"读数、跨区域色调比较 | **固定元件、变动背景，看读数动不动** |
| **② 自发光 / 辉光** | 边缘柔和，不形成平涂区域；辉光细丝还会制造 1px 游程 | `flatShare`（系统性低估）、发光元素面积、笔画游程 | 找同一元素在无辉光状态下的样子 |
| **③ 全局后处理**（渐晕／色彩分级／颗粒／景深／锐化） | 同一个色板 token 在屏幕不同位置读出不同值 | 跨位置颜色比较、空间细节分布 | **同一元件在屏幕不同位置取样** |
| **④ 信箱黑边** | 常数污染：本文所有实机截图**上下各 80px 纯 `#000000` = 整帧 10.0%** | 直方图、最暗档占比、均值亮度、覆盖黑边的空间格 | 先测黑边，再剔除 |
| **⑤ 遮挡顺序** | 你以为在测 A 层，实际测的是压在上面的 B 层 | 任何按包围盒求平均得到的颜色 | 1:1 切开看 |

#### 我做过的三个判别实验

**实验一 · 固定元件，变动背景（判决性）**

实机 ui-03（主界面）与 ui-07（开放世界 HUD）里出现了**同一个组件**：`⚡ 6435 /9800  100 % 🔒` 状态胶囊。两帧背景天差地别：

| | 背景状况 | 胶囊填充（逐列模态色） |
| --- | --- | --- |
| ui-03 | 近黑表盘，背景亮度约 **0.10** | (42,40,40) – (49,47,47) |
| ui-07 | 场景亮度在同一帧内从 **0.317 到 0.994**（含近纯白的雾） | (42,41,43) – (43,42,44) |

**背景亮度差最高达 0.9，胶囊填充只动了 ≤7/255（≤2.7%）。→ 这条胶囊不透明，实测值就是设计值：约 `#2B2929`。**

> **这是本次分析里唯一一个判决性的分层结论。** 它的形式是可复制的方法：**固定元件、让背景变，看元件动不动。**

**实验二 · 同一元件在屏幕不同位置（渐晕的存在证据）**

主菜单左侧四个**同款**按钮，填充实测：

```
最上 205,205,203  →  199,199,199  →  197,197,195  →  195,195,191  最下
```

单调递减 **10/255**。四个按钮设计相同，背景却不同（表盘环、暗底、地图各在其后）。

**结论：屏幕上存在一层全局渐晕／垂直分级，同时压暗所有元件。** 所以"某面板的填充色是 X"这句话必须加限定：**它在屏幕上下两端可以差 4%。**

**实验三 · 白纸上的实心色带**

标题页那条"满幅黄带"，在纯纸面区实测 (245–252, 237–243, 107–112)，**R−G ≈ +8**；靠近人物边缘处变成 (210,213,90) 与 (216,221,105)，**R−G ≈ −3 至 −5**。

**色相在带内翻转了。** 这正是 `flatColors` 为什么测出**两个不同的黄**（`#FAF139` 0.53% 与 `#F9EF3D` 0.52%）——它们不是两个色板值，**是同一条带在不同底上的两种合成结果**。

#### 因此被修正的结论

| 原结论 | 修正后 |
| --- | --- |
| "四年 48.1% → 48.0%，完全未变" | **错**。剔除 10% 黑边后是 48.1% → **≈42%**，差约 6 个百分点 |
| "大块隐含不透明度 0.329–0.457，大块也是淡的" | 只成立为**合成后亮度覆盖**；**不能读作设计不透明度**。设计值可能是"中灰不透明"，也可能是"半透明白" |
| "`flatShare` = 强调色预算" | 它测的是**平涂存活量**。满幅黄带只有 1.0%，色相簇却是 4.55% |
| "浅色磨砂面板" | 面板层级实测确认为 `#2B2929` 与 `#C3C3BF`–`#CDCBCB`；但**"磨砂"是否为半透明，未判定** |
| "标题页 86.3% 是单一区域" | 区域检测已把黑边当底色排除，该区域跨越内容区；按内容区算是 **95.9%** |

#### 不受影响的部分（已核对）

- **字号 28 / 30 / 68px、行长 1285px**：在内容区内测量，且**文字是不透明的**——文字压在什么上都不改变它的墨迹高度。
- **官网／CSS 的色值频次**：来自源文件，与合成无关。
- **字体谱系（Novecento）**：来自源文件与仓库，与合成无关。
- **信箱黑边对笔画游程统计几乎无影响**：纯黑长条产生的是一条超长游程，不进 1–8px 分箱。

| **状态胶囊是否半透明** | ✅ **已解决**：不透明，α ≥ 0.942，两种独立方法互证 | — |
| **`进入俯瞰` 提示胶囊** | ✅ **已解决**：近白 `#FDFCFC` 不透明面板 | — |
| **浅色磨砂面板（主菜单按钮）是否半透明** | ⚠️ **仍未解决**，且比原先更麻烦：三段录像里**没有主菜单画面**；更要紧的是**主菜单背景是静止的地图，即使录了主菜单也无法用回归判定**（背景不动 → 无激励） | 唯一路径：**测"面板滑入／淡入的过渡帧"**——那一刻面板压在世界之上而世界在动；否则只能解包资源 |
| **战斗 HUD 面板（队伍血条底、技能冷却环）是否半透明** | 未测（素材已有） | `video-probe alpha` 在 t=5–18s 段；**比率法在剧烈运动段依然成立**（它不需要相关性） |
| **动效曲线、缓动、转场时长** | 未测（素材已有） | `video-probe motion` 逐帧 + 拟合 |
| **场景像素与 UI 像素不可分离** | 部分缓解（可人工选 ROI 避场景） | 人工遮罩 |
| 各层的确切 α 值 | 仍不可得 | 只靠最终合成值反推不出；需要官方资源或分离图层 |

> **录像分析的硬教训：先分段，再回归。**
> 这 20 秒录像**不是一次连续平移**——t≈4.5s 处探索 HUD 整块换成战斗 HUD（见 5.9）。把两段混在一起做回归，得到的是"方差比 0.733、alpha≈0.27"这样一个**自信的错答案**；用 `--start` 分段之后，同一素材给出 α ≥ 0.942 的正确答案。
> **真实录像永远不会是"一段"。** 所以流程必须是：`motion` 找切换点 → `--start/--max` 选出稳定段 → 才轮到 `alpha`。

#### 一条通用规则

> **做这类拆解时，每个数字都要标注它是"合成值"还是"设计值"。**
> 合成值可以比较、可以定位、可以作为规格的**约束**；但一旦你把合成值当成设计值写进规范（例如"大块不透明度 ≤0.5"），你就是在照着别人的显示器校准自己的画布。

## 10. 一句话收尾

终末地的设计语言之所以成立，不是因为它"很科幻"，而是因为它**借用了一套真实存在的、有功能理由的视觉系统**——工程图纸的网格、地图的等高线、仪器的刻度、钣金的切角、测绘的十字、机器的喷漆贴标。

**里面每一个图形都能回答"它在真实世界里是干什么用的"。** 这是它可以被学习、也可以被照做的原因；也是绝大多数"仿终末地风格"失败的原因——它们照抄了形状，却没有抄来形状背后的理由。
