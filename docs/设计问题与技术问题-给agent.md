# 设计问题与技术问题：一次真实交付的复盘

> 来源：把《明日方舟：终末地》的视觉语言做成一份 10 页 PPT 的完整过程。
> 每一条都是我实际犯的错，带当时的数字或代码。**给 agent 用：看到症状 → 认出失效模式 → 执行规则。**
>
> 阅读顺序：先读 §0（元规则），再按需查 §1（设计）或 §2（技术）。

## 0 · 两条元规则

这一整轮里最贵的教训不是任何一条具体规则，而是下面这两条。它们各自都骗过我，而且骗得很成功。

### 0.1 指标是手段，不是目的

**症状**：用户说"你的修改对人眼几乎不可见"。

我为了在对标里追平参考的"可分辨色数"，在近黑底上铺了 **300 个 2–3px 的斑点**。色数从 234 涨到 553——**看起来是进步**。

但斑点位置用 `x = (i*977+137) % 1920` 生成，**那是等差数列，不是随机**：在 1920×1080 上凑出了可见的周期点阵加摩尔纹。而且斑点比底亮 16 级，根本不是亚阈值。

撤掉点阵后，色数 **553 → 549**。

**也就是说：那片肉眼清晰可见的花纹，在指标上几乎不存在。** 指标压根没看见眼睛看见的东西。

**规则**：
- 任何"提升指标"的改动，改完**必须看**。没看过的指标提升不算改进。
- 一个数变好而画面变坏时，**相信画面**。
- 追一个自己没有能力验证的数，就会开始伪造。

### 0.2 套规则之前，先问这个元素在这里是干什么用的

**症状**：用户说"你把图片做成黑白的了，这样没法做参考的"。

我的技能清单里有一条"把插画并入色板"的手法（双色调），我就给九张参考图全加上了 `--mix 1`。

**而这一册的主角恰恰是颜色本身**：有一整页在论证"整个游戏只有一个黄"，另有一页讲强调色预算。去色以后：
- "只有一个黄"那页的配图（产线黄线）是灰的
- "一大块平涂黄是错的"那页，那块黄是灰块

**我把图放在那里就是为了提供颜色证据，然后我把证据抹了。**

**规则**：
- **统一手法不能吃掉内容。** 需要让图和页面融合时，用**边缘**（羽化、框线），不要用**色调**，除非图的颜色本身不是信息。
- 从清单里取一条手法时，先回答："这个元素承担什么信息？这条手法会不会动到它？"

## 1 · 设计问题

### 1.1 面积占比相同 ≠ 设计相同

**症状**：参考里一个区域占画布 42%，我放了一个占 42% 的**纯色块**。用户指出："像素占比上近似，但不存在设计性。"

面积对上了，设计性为零。

**度量方法**（取该区域矩形，统计两件事）：

```
主导平涂色占比 = 出现次数最多的 RGB 占该区域的比例
可分辨色数     = 区域内不同 RGB 的个数
```

**实测对照**：

| 取样 | 主导平涂 | 可分辨色数 |
| --- | --- | --- |
| 参考：主界面左缘 UI 底 | **3.0%** | **1383** |
| 参考：主界面右下 UI 底 | 20.8% | 196 |
| 参考：邮箱空面板 | 19.6% | 188 |
| 参考：背包下面板 | 14.5% | 7032 |
| **不合格**：我的浅色面板（修前） | **87.6%** | **191** |
| **不合格**：我的封面底（修前） | **42.8%** | **327** |
| 修后：焦点面板 | 29.0% | 417 |
| 修后：封面底 | 3.5% | 234 |

**规则**：
- 大区域主导平涂 **< 25%**；可分辨色数 **200–7000**（视职务：安静承载面 188–200，制图底 1383–7032）。
- **判据**：把这块区域的文字全删掉，它还读起来像"一块被设计过的面板"吗？如果只像色块，缺的是下面 §1.2 的层级。

### 1.2 细节 ≠ 层级

补细节只解决"可分辨色数"，不解决"它像不像一块被设计过的东西"。

**手段（按成本）**：
1. **亚阈值颗粒**：一个 `noise` 源 + `blend`，极低 amount。⚠️ 见 §2.4 的中间调陷阱。
2. **细横纹**：参考纸面实测有强横向线结构（`rowStrength` 0.915）。十几条 1px 发丝线，对比度压到 1.06–1.1:1。
3. **斑点场**：1–2px 小点。⚠️ **必须真随机**，见 §0.1。

**层级（这五条才是关键）**：
- 1px 顶边高光（"这是一块被照亮的实体"）
- 四角对位括号（"这是被框定的一栏"）
- 一行拉丁微标签 + 一条发丝线（"这一栏有名字"）
- 内部文字的三级重量（标签 / 值 / 单位）
- 一处局部渐隐（纹理在这里出现又消失，而不是均匀铺满）

### 1.3 只能 UI 比 UI，不能 UI 比画面内容

**症状**：我拿自己的版面底去比参考里**表盘内的地形渲染**（2926 色），得出"少 9 倍设计"的结论。

**那是画面内容，不是 UI 底色。** 换成真正的 UI 底色后，参考区间是 188–7032，我的 234/417 落在区间内。

**规则**：量之前先确认，你量的那块在参考里是"设计的表面"还是"呈现的内容"。**比错了对象，结论一定错。**

### 1.4 一个模板盖十次 ≠ 十张设计图

**症状**：我第一版十页共用同一套页眉、页脚、88px 边距、同一底盘。用户："你几乎是把之前的拆解做成流程报告了。"

**十页长得一样，无论内容是不是一回事。**

**修法**：删掉全部共享模板。每页自己决定边距、尺度、焦点装置、排布方式：

| | 构图 |
|---|---|
| 01 | 满幅出血、字体主导 |
| 02 | 对分到边、缝在正中 |
| 03 | 论点 + 一大块色（反例） |
| 04 | 居中纵轴，纯字体页、无面板 |
| 05 | 满宽标本带，2×6 |
| 06 | 图版 + 实拍，重心左下 |
| 07 | **实拍为主体，字落在它让出的空间里** |
| 08 | 三句话、行高不等 |
| 09 | 编辑型列表，右留白装范本 |
| 10 | 近乎空页，一句话 |

**规则**：整页渲染一秒出头，十张独立构图根本不贵。**共享一套语言，不共享一套骨架。**

### 1.5 母题要换职务，不是一个母题用到底

**症状**：我挑中"等高线"，然后把**同一个同心椭圆簇**摆在了七个页面的角上——同一种形态、同一个尺度、零功能。用户："这是纯粹的参数近似，压根不是一整套设计。"

**终末地自己**：等高线出现在 logo 里（作为标识填充）、表盘中心（整页主体）、纸面底纹（1.06:1）、地名标注（小记号）、到处都在，**但每处形态和尺度都不同**。

**修法**：一个母题，五种形态、六种职务：

| 职务 | 出现的页 | 形态 |
|---|---|---|
| 底纹 | 纸面 / 收尾页 | 开放的流动曲线 |
| 主体 | 地图页 | 实拍全尺度 |
| 边界 | 标本带 | 不规则闭合等高区 |
| 标注 | 封面 / 标本 / 深度页 | 三环小记号 + 地名微标签 |
| 场 | 收尾页 | 稀疏平行 |
| 标本 | 形态页其中一格 | 经典同心环 |

**规则**：一个母题要出现多次，**每次必须换一个职务、换一个尺度、换一种画法**。若你说不出这次它是干什么用的，那它就是贴纸。

**附**：**装饰性是合法的。** 我把分析文档里"无信息角色的装饰禁止"那条规则错误地套到了给人看的 PPT 上——那条规则是给**分析**用的（防止拿装饰冒充信息），不是给版面的。**PPT 的画面复杂度本身就是价值。** 我因此做了一组 `incident()` 装饰件（点阵 + 刻度尺 + 十字 + 小椭圆），部署到六页。

### 1.6 明暗逻辑：暗底上亮的，亮底上暗的

**症状**：页面讲"明暗对比"，我却在暗半边压了一块大白板，还多出第三个灰调区，把对比毁掉了。同时我把 `#2B2929`、`#4A4E4C` 的深色标本放在近黑底上——**读起来是洞**；`#191919`、`#0A0B0C` 的色卡在暗底上**根本看不见**。

**规则（硬规则）**：
- **炭底只用浅色墨，纸面只用深色墨。**
- 深色标本只在"深色面板本身是主题"的地方出现，且要带浅色括号和浅色文字，不能是一块孤立的暗块。
- 用一页的**结构**演示对比，而不是用一块压上去的色板。例：把一句话拆开架在缝上——前半深墨在纸上，后半浅墨在炭上。

### 1.7 页面必须演示它自己的论点

**症状**：一页标题写着"整个游戏只有一个黄"，而**整页几乎没有黄**。最大的色块是一条白色正弦波（还读成声波不像地形）和两块浅色板。

**用户**："你倒是放点黄色的展示啊，一大坨黄色也行，还可以举例一些运用场景。"

**修法**：
- 放**最大的一块黄**做**反例**（"这么多黄，等于没有黄"）
- 放**正确的一屏**（几乎全暗，只留一处黄）
- 放**四个真实用法**，每一个都真的带黄：`6435`（数值）、状态环 + `运行中`（状态）、带节点的黄路径（流向）、黄页签 `工业计划`（当前项）

**规则**：**没有演示的页面是说明文字，不是幻灯片。** 对错并置，比只讲对的一边有效。

### 1.8 配图要截"这页要证明的东西"

**症状**：一页讲"两张底（明/暗）"，我截的却是 UI 主体（商品卡），底只占很少。

**那一页的重点是"底"**——底变了，规矩就变了。所以要整屏取景，让纸面和炭底的占比成为主角。

**规则**：先回答"这页在证明什么"，再决定截哪里。**取景是论点的一部分，不是配图。**

### 1.9 声称了对比，图里就必须有两个项

**症状**：我在 p06 说"一整块面板压在一个活着的世界上"，配图却是把面板裁到只剩面板本身。

**用户**："你自己说的要展示磨砂效果，那肯定要有对比啊。"

**修法**：整屏取景（`2440×1480`），版位从 `724×250` 放大到 `724×440`。现在世界在面板的**四边和下面**都露出来：左边机械、右上建筑、右边站着的角色、下面还露着技能栏。

**规则**：**对比成立的前提是两个项都在画面里。** 声称 A 压在 B 上，就把 A 和 B 一起截进来。

### 1.10 框还是羽化，看边缘环境

**症状**：我给所有图统一加边缘羽化。但有些图**周围元素太密，没有可供渐变过渡的对象**——羽化失效，图变成"漂浮的软边盒子"。

**用户**："p5 和 p9 的图片可以加方框，因为边缘元素太多，透明渐变无法实现有效过渡，你可以参考终末地自己的风格加个框。"

**修法**：参考游戏里自己的面板（标题条 + 浅面板 + 1px 描边 + 四角括号），写一个 `panelPlate()`：**深色衬底(4px) + 1px 描边 + 顶边高光(1px 近白) + 四角括号**，源图重切为**硬边**（`--feather 0`）。

**规则**：
- 图落在**开阔的底**上 → 羽化，让它溶解进页面
- 图落在**密集的元素之间** → 加框，让它坐进页面
- 加框时**核对坐标**，确认没有压住别的内容（例：衬底占 y 846–1016；标本标签到 796 结束，说明文字在 1032）

### 1.11 外面发光 = 漂浮的软边盒子

我试过给图加外发光，结果是一块**发光的矩形**——正是我自己规则里禁止的"自由漂浮的软边盒子"。**做出来才确认不行**，这个否掉的记录留下了。

**规则**：否掉的方案也要留记录，附上它的失败原因。否则下一个人会再试一遍。

### 1.12 裁切：切一点点是最糟的

封面上巨型字标被画布边缘切掉 **54px**（约占一个字宽的 17%）。**既不像刻意的裁切，也不干净。**

**规则**：出血要么**完全没有**，要么**切得明确**（半个字、整个字）。中间状态读作失误。

### 1.13 自用笔记不能进交付物

**症状**：我写进了正文：`要抄的话，先问：` / `它在我的页面里，是地图，还是花纹？` / `如果是花纹，删掉。`

**那是写给我自己的。** 用户："记得去除你写给自己看的话，比如怎么抄。"

**规则**：交付前逐句问——**这句话是写给读者的，还是写给我自己的？** 判据：出现"我的页面""先问""如果是……就删掉"这类指向作者动作的措辞，就是私note。

## 2 · 技术问题

### 2.1 长度 ≤1 是画布比例，不是像素 ⚠️ 最危险

**症状**：我写 `rect(x, y, 1, 1, '#0F1213')` 想做 1px 斑点。

**实际得到：一个铺满整幅画布的不透明矩形**（`1` = 100%）。

300 个"斑点"里有 200 个是满幅覆盖，把整页底冲成灰色：**主导平涂 3.5% → 54.4%，可分辨色数 234 → 118，而引擎零报错。** 缩略图上看起来只是"有点脏"。

**规则**：
- **任何"1px 的点"都必须写 ≥2。**
- 想要出血的边用**像素值**（`-20`、`W + 40`），不要用 1。
- 渲染完必须跑一次整页统计。这类错误在缩略图上看不出来。

#### 2.1.1 缩放会把尺寸推进那个区间 ⚠️ 我第二次栽在同一条上

**症状**：我先按 450×800 的设计空间画好框内内容（细线写 `h: 2`），再统一乘 `0.48` 缩到 216×384。
结果画面里出现**两条 2385px 高、贯穿全图的长条**。

**根因**：`2 × 0.48 = 0.96`，落在 `0 ≤ 值 ≤ 1` 里，于是被当成「画布高度的 96%」＝ 2385px。

**这条比 2.1 更阴**：源码里每一个数都是对的、可读的、遵守了「≥2」的规则；
**错误是缩放之后才产生的**，所以读代码看不出来，只有渲染出来才现形。

**规则**：
- **能按最终尺寸画就按最终尺寸画，不要「先画大再缩」。** 缩放不是免费的重构，
  它会把所有尺寸推过一条你自己看不见的阈值。
- 若确实要缩放，**缩放之后再过一遍**：任何 `w/h/radius/描边宽` 落在 `0..1` 的值都要夹到 ≥2（或改成比例的真实意图）。
- 一个自查方法：渲染后按报告找「宽 < 300 却高 > 600」的层。这个形状组合在这类错误里必然出现。

### 2.2 形状辅助函数的返回类型：单对象 vs 数组

**症状**：`chamfer/tab/ring/arc` 返回**单个图层对象**，我却用 `...` 展开 → `TypeError` → **整个模块抛错，一张场景都没写出来。**

**而报告说 "layer failures = 0"**——因为渲染读的是**上一次的旧场景文件**。

同理反向：把返回数组的函数 `L.push(chamfer(...))` 不加展开，会得到 `shape: "undefined"` 的图层。

**规则**：
- 写辅助函数时**统一约定**并在文件头注明：单层返回对象（`push`），多层返回数组（`...` 展开）。
- **不要混用。** 这一轮我犯了 3 次同样的错。

### 2.3 "layer failures = 0" 是假绿 ⚠️ 骗了我三次

**症状**：生成器崩了 → 场景没重写 → 渲染读旧文件 → **报告输出"零失败"**。

**规则——固定的检查顺序**：
1. **先看生成器自己有没有报错**（`node --check` + 运行输出）
2. 再看渲染的 `layer failures`
3. **再看产物时间戳**（确认这次真的重写了）

只要跳过第 1 步，第 2 步就是假绿。

### 2.4 `filmGrain` 预设在近黑底上等于没做

现成预设用 `luminanceMask` 把颗粒限制在**中间调**（`stops: ["#000000","#FFFFFF","#000000"]`）。

**套到近黑底上，遮罩值 ≈ 0，什么都不会发生。**

**修法**：自己写图，去掉那个遮罩：

```js
{ graph: [
  { op: 'noise', amount: 0.5, seed, base: '#808080', monochrome: true,
    as: 'grain', produces: true, expectNoChange: true },
  { op: 'blend', base: 'input', over: 'grain', amount },
]}
```

### 2.5 永不用 PowerShell 改写源码文件 ⚠️ 毁过一次文件

**症状**：用 `Set-Content` 回写 `build.mjs` 做批量替换，**UTF-8 被毁**：
- 每个损坏点吃掉「字符串最后一个字 **和** 收尾引号」：`txt('读得下去。', …)` → `txt('读得下去\uFFFD?, …`
- 行尾 `//` 注释里**连换行一起吃掉**，导致下一行代码被注释吞掉
- 116 行受影响

**然后我用正则修，两次都让情况更糟**（`看这----`、`---承载----可操作面`——二次损坏）。

**规则**：
- **源码文件只用文件工具改**（它们正确处理 UTF-8）。
- 必须批量改时：**写 Node 脚本**改，不要用 shell 重定向。
- **每一遍都跑 `node --check`**，不能只在最后跑一次。
- 修不干净就**别纠缠**，重写文件。补丁叠加到一个已经损坏的文件上，损伤是指数级的。

### 2.6 产物就是备份

**这一轮唯一救了我的一件事**：场景 JSON 从未被动过。

- 生成器死了，但**十页 PNG 完好**、**场景 JSON 完好**
- 我甚至能**用完好的产物当字典去修源码**：从 `scenes/*.json` 里抽出全部渲染文本（166 条），按前缀匹配恢复源码里坏掉的字符串（恢复了 88–109 处 + 多处换行）

**规则**：
- **生成的中间产物要留在盘上**，不要只留源码。它是你的备份，也是你的字典。
- 场景 JSON 完好时，可以绕过生成器**直接在场景层改**——版面和文字都在里面。

### 2.7 `fit: cover` 会裁，比例要算不要猜

**症状**：我把源图放进版位时只写 `fit: cover`，结果宽高比差到 **7.5 倍**。

| 页 | 放置比例 | 源图比例 | 倍数 |
|---|---|---|---|
| p05 | 12.3 | 1.63 | **7.5×** |
| p03 | 3.57 | 1.69 | 2.1× |
| p06 | 2.90 | 1.58 | 1.8× |

主体必然被切歪。

**修法**：不是挪版位，**是按版位比例重新切源图**——横条的版位就切源图里本来就是横条的区域（据点面板的字段行、产线的俯视带）。修完 p03 是 3.46 vs 3.68、p06 是 2.90 vs 2.88，**精确匹配**。

**规则**：
- 每次放图都算一遍 `放置比例 ÷ 源图比例`。
- **素材的宽高比是约束，不是事后要迁就的东西。**
- 想放成横条，就去源图里找本来就是横条的区域，不要压扁一张方图。

### 2.8 CJK 与 latn-only 字体：静默变豆腐

`MonoTech`（Cascadia Mono）、`Grotesk`（Bahnschrift）**只声明 `scripts: ["latn"]`**。把中文交给它们会渲染成豆腐块，**引擎不报任何警告**。

**修法**：写一个脚本路由器：

```js
const hasCJK = s => /[\u2E80-\u303F\u3400-\u4DBF\u4E00-\u9FFF\uF900-\uFAFF\uFE30-\uFE4F\uFF00-\uFFEF]/.test(String(s))
const fontOf = s => (hasCJK(s) ? 'HanSansMedium' : 'MonoTech')
```

**规则**：任何"拉丁等宽/无衬线"字体，**默认它不覆盖中文**，除非你实测过。

### 2.9 其他引擎细节

- **`line` 用 `x1,y1,x2,y2`，不用 `x/y`**。写成 `{x, y, x2, y2}` 会从画布角画出一条对角线。
- **`polygon` 至少 3 个点**；做切角/梯形用 `path` 更省事。
- **`design_palette apply` 的参数顺序**是 `apply <image> <preset>`，颠倒了会报 `unknown preset "<图片路径>"`。
- **中文转义**：在必须保证纯 ASCII 的场景里，用 JS 的 `'\u7EC8\u672B\u5730'`（终末地）代替字面量。这在我修好后仍然保留在封面那一行——**它现在是防弹的**。

### 2.10 sandbox 下的子进程与网络

- Node `child_process` 用默认 `stdio: 'pipe'` 在沙箱下会 **EPERM**（不能开命名管道）。改用**文件描述符重定向**，或 `stdio: 'inherit'`。
- `pwsh` 里的 `curl` 默认被网络策略挡住（`schannel: AcquireCredentialsHandle failed`），需要一次性提权重试。
- 大文件下载必须 `run_in_background: true`，前台会被中断。

### 2.11 视频测量：先分段，再下结论

20 秒的录像在 t≈4.5s 处从探索 HUD 切到战斗 HUD。**不指定起始时间直接测，量到的是两个世界的混合**，会给出一个自信的错误答案（比值 0.733，α≈0.27）。

加上 `--start` 分段后，α ≥ 0.942。

**规则**：**先确认片段里是同一个状态，再测。** 换段会污染统计，而统计不会告诉你它被污染了。

### 2.12 在成品上量，且要量屏幕上的那个字

两条都是「量测本身没错，被量的东西错了」。

**第一条：被量的对象必须是交付的那张图。** 一张海报的文字对比是在 **hero 合成图**上量的
——那是深色场、区域双色调与网点**之前**的状态。在成品 PNG 上同样九区：顶带掉到 3.7:1、
引文掉到 3.9:1。报出的每一个「8.4:1」说的都是另一张图。

**第二条（更贵）：声明的颜色和屏幕上的字可以不是一回事。**

症状：两版文字，守卫一直报「**80 层全部 ≥ 4.5:1**」——全绿，而字是灰的，1:1 裁切里
看得很清楚：灰字带一圈黑边。

根因是 `outerGlow` 配了 `blend: 'normal'`：它把暗色**盖在笔画上**。它不改声明的墨色，
也不改底子，它改的是**字形**。于是凡是拿「声明墨色 vs 底子」作比较的检查，两个输入都没变，
自然什么都看不见。

**规则三条：**
1. 量对比要在**交付的那张 PNG** 上量，不是在某个中间图层上量。
2. 引擎现在把文字层声明的墨色写进 `report.json` 的 `drawn.paint`——检查要拿它和**屏幕上实测的
   墨核**比一次，比值 ≥ 1.3 就是「屏幕上的墨不是声明的墨」。
3. 「对比度不够」和「字被盖住了」是两个毛病，**量对比度量不出后者**。这一条只有 1:1 裁切能看出来。
   工具量得到的东西有边界，遇到全绿但看着不对时，边界就在这儿。

**量测方法本身踩过的坑**（记下来，因为每个都看着很合理）：
- 「文字框里最暗的像素 vs 最亮的像素」——小字号下**框内两端都是字形**，把普通的抗锯齿数字报成 2.5:1。
- 「按亮度直方图 Otsu 切两段」——在一个含地图的区里，它找到的是**两种山体颜色**，于是报 1.5:1。
  直方图分不开字形和风景。
- 「取两类的均值」——44px 的字，**大部分像素是抗锯齿边缘**，均值把 #EAF2FA 量成 #DBE3EB。
  字形要取**墨核**（暗墨取最暗的十分位，亮墨取最亮的十分位）。
- 定性类归属**不能用被污染的均值**判断：亮墨的均值会低于暗底子的均值，于是整份报告的正负号反了。

正解是**竞争分配**：两个中心，每个像素投给更近的一个，取两类的中心；中心以**声明墨色**与
**区框边缘的中位色**为种子，归属**从种子来**而不是事后比距离。

→ 工具：`node bin/design.mjs check-render out/poster.png --report out/poster.report.json`

### 2.13 提示词里的要求会被跳过；能失败的才留得住

**实测**：某版本常驻 policy 要求「动第一个元素前先答四问」。查会话记录的 `system` 字段——
**它确实在每一次请求里**。而接下来那一场，17 版全部在第 4 层（形式）动手，四问一次没写。

**规则**：**常驻不等于有约束力。** 唯一躲不掉的形态是「跳过了就没有产物」。
所以四问现在是**渲染的前置条件**：场景没有 `gates` 块 → 渲染器拒绝、非零退出、不写文件。

配套的两条：
- 常驻段只放**能失败**的规则（每条对应一个返回非零的检查）；无法这样强制的全部进 skill。
  上一版常驻段 15,640 字符 / 22 条原则，压到 4,245 字符 / 6 条可强制规则；补进 11 步判定顺序之后
  是 5,725 字符 / 6 条 —— **仍然比原来低 63%，而可强制的规则从 0 变成 6 条。**
- `--no-gates` 必须是**显式**逃生门。默认放行等于回到这道闸门要打破的那种沉默。

### 2.13.1 顺序本身也可以进判据，而且它必须进

11 步判定顺序（清点→判语言→定动线→**定光轴**→分明暗→分角色→分饱和→交错→造型→效果→质感）
来自四门合成课的合并结论。**写成散文它是一段被略读的段落；写进判据，"跳过了一步"就变成出不了图。**

现在它是 `src/gates.mjs` 里的 `DECISION_SEQUENCE`，数据，所以拒绝信息能把它印出来、调用方能照抄。
`gates.sequence` 少一步、多一条、顺序颠倒，渲染器都拒绝。

**能跳的步必须给原因**（`{ why: "..." }`，why 不能空）——**"不适用"和"没想到"从外面看一模一样**，
而后者是这一整类失败里最贵的一种。有几个步列在不可跳名单里：清点、动线、光轴。

**判据自己踩的两个坑，都值得记：**

1. **数组形式里"位置即顺序"，所以数组项不能带步名。** 第一版允许 `{ step, ... }`，
   于是「把光轴挪到最后」永远检测不到——**判据循环依赖了它要验证的那个顺序**。
   现在：数组项只能是字符串；要指名就用对象形式，那里的顺序是可查的。
2. **数组元素的"对象形式"正是标不适用的合法写法**，而第一版把对象一律判死为"必须是字符串"。
   引擎自己的分镜表就撞上了：三个标不适用的步被拒，**理由是判据对自己契约的理解错了**。

**一般化**：写判据时先问「它验证的那个东西，是不是也被它当成了输入」。是的话，它永远验不出问题。

### 2.13.2 检查的代价要随风险走，算术答过的地方不要再花一次看

用户原话：**「在必须有实物验证的时候再跑实物，考虑效率」**。

`H4b` 因此分两路：
- 声明了 `forbiddenZones` 而**几何上不相交** → PASS，明说「不需要看图」。不裁图、不留物证、零代价。
- **真的相交** → 报出位置、占禁区比例、不透明度，并打印一条**可直接执行**的 1:1 裁切命令。

理由是**几何相交不等于视觉遮挡**：一片近乎透明的纹理压过脸是合法设计，一块不透明板压过去是事故——
而这不是规则能回答的问题，闸门也不猜。它做免费的那一半（算术），把另一半交出去，代价是一张裁切图。

**裁切命令是算好印出来的**，不是"去那里看一眼"——**把区域翻译成坐标这一步，正是人累的时候会跳过的那一步**。
测试里验证了那条命令真的跑得通：一句不能执行的指示等于没给。

### 2.14 改了源、没部署 —— 最安静的一种断路

**实测事故**：`design/agent.cordis.yml` 改了一大轮并加了两个闸门，校验做了三层——
YAML 用真解析器过了、行数统计过了、还写了独立的 `verify-preset-yaml.mjs`。**全部通过。**
而 `deploy-preset.mjs` 从没跑过，harness 加载的仍是旧的 **402 行**版本。

**所有校验都在验源文件，活的那一份是旧的。** 更坏的是：那批校验越漂亮，越让人以为已经生效。

**规则**：
- 改 `design/` 之后**必须** `node deploy-preset.mjs`；`--check` 的退出码是 **0 一致 / 1 漂移 / 2 未安装**。
- 验收要指向**已部署**的那一份，不是源。仓库根目录的 `verify-preset-live.mjs` 就是干这个的：
  它读 `~/.dsh/.agent-presets/design/`，量 policy 的字符数与规则条数、查九个 skill 的 frontmatter、
  并**真的拿一个无 gates 的场景去渲染**，确认它被拒绝。
- 一般化：**任何"改了就生效"的假设都要有一条会失败的检查**，否则它只是一句信念。

### 2.15 效果规格里的 `blend` 拼错会静默退回 source-over

`overImage` 只实现了 `multiply` 与 `screen`，其余模式**没有 else 分支**——于是任何拼错
（`softLight` 而非 `soft-light`）都退回 `normal`，**报告干净、画面看着仍然是有意为之**。
比丢层更坏：丢层留下空白，这个留下一个「看起来像设计决定」的错画面。

**实测对照**：`blend:'softLight'` 与 `blend:'normal'` 相差 **0 像素**、0 条警告；
而本意的 `multiply` 相差 6400 像素。

**现在**：`assertBlendMode` 统一校验，图层路径与效果路径**共用同一套词汇与同一句错误信息**，
失败走和失败图层**同一个通道**（进 `warnings`），不另开第二条。
