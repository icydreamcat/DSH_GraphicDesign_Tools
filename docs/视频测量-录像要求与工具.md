# 视频测量：录像要求与工具说明

这份文档回答一件事：**你要录什么，我怎么测，结果有多可信。**

---

## 1. 工具已就绪，并且已验证

| 工具 | 位置 | 作用 |
| --- | --- | --- |
| `video-probe.mjs` | 引擎工具目录，已注册 | `info` / `frames` / `track` / `alpha` / `motion` |
| `make-alpha-fixture.mjs` | 引擎工具目录，已注册 | 生成**已知 α** 的合成素材，用来验证上面的工具 |
| `ffmpeg` 6.0-essentials | `D:\DSH_GDT\tools\bin\ffmpeg.exe` | 解码。**ffprobe 没装**，`info` 走 ffmpeg stderr 回退路径，实测可用 |

**输入可以是视频文件，也可以是一个 PNG 帧序列目录** —— 后者完全不需要解码器。

### 验证结果（这是能不能信任它的前提）

用合成素材跑，真值写在 `truth.json` 里：

| 素材 | 真值 α | 实测 α | 还原的元素色 | 判定 |
| --- | --- | --- | --- | --- |
| 不透明 | 1.00 | slope 0.0000 ×3 | — | **OPAQUE** ✓ |
| 半透明 | 0.50 | **0.500** | `#ffffff` ✓ | **TRANSLUCENT** ✓ |
| 半透明 | 0.25 | **0.250** | `#ffffff` ✓ | **TRANSLUCENT** ✓ |
| 背景静止 | 0.50 | 激励 0% | — | **CANNOT DECIDE** ✓ |

**它同时会算对、也会在该拒绝时拒绝。**

### 编码带来的偏置（重要，你录像必然遇到）

同一素材编成 H.264 后重测：

| 编码 | 实测 α（真值 0.50） | 偏置 |
| --- | --- | --- |
| crf 18（近乎无损） | 0.481 | −0.019 |
| crf 30（重度压缩） | 0.490 | −0.010 |

**结论：偏置是 ±0.02 量级的散度，不是系统性偏移**（crf 30 反而更准）。所以你的录像**不需要无损**，正常画质够用。

> 注意：`ffmpeg` 报 `yuv420p(tv, ...)` 是 limited range。这个线性缩放**会在回归斜率里约掉**，所以不影响 α。**非线性调色（滤镜、HDR 转 SDR）会**，所以请关掉 HDR。

## 2. 为什么必须动起来

单帧里，"中灰不透明面板"和"深底上的半透明白面板"**产生完全相同的像素**，数学上不可区分。

一旦背景动起来就分开了：

```
合成值 = α·元件色 + (1−α)·背景色
对背景做回归 → 斜率 = 1−α  →  α = 1 − 斜率
```

**斜率直接给出 α 的数值，不只是"是/否"。** 而且这个估计对线性色调缩放免疫。

## 5. 我会跑的命令

```powershell
# 1) 先看素材本身（分辨率、帧率、是否 limited range、有没有黑边风险）
node tools/video-probe.mjs info <你的录像>

# 2) 找剪切点——剪切会破坏"邻近背景"假设，得避开
node tools/video-probe.mjs motion <你的录像>

# 3) 逐帧追踪某个 HUD 元件的读数
node tools/video-probe.mjs track <你的录像> <x> <y> <w> <h>

# 4) 判决：不透明 / 半透明（含 α 数值）/ 无法判定
node tools/video-probe.mjs alpha <你的录像> --rois hx,hy,hw,hh,bx,by,bw,bh
```

坐标是**画布分数**（0–1），所以换分辨率不用改。

`alpha` 需要两个 ROI：
- **元件 ROI**：面板填充上**没有文字、没有图标**的一小块
- **背景 ROI**：紧邻它、在同一个高度上、**不被元件遮挡**的一块

工具会自己判断够不够判定，不够就输出 `CANNOT DECIDE` 并说明原因，**不会编一个数给你**。

## 6. 三段录像已经给出的结论

### 已经判定（不透明）

| 元件 | 结果 |
| --- | --- |
| 顶部状态胶囊 `⚡6435/9800 100%` | **不透明**，α ≥ 0.942，R²=0.951–0.959，方差比 0.058 |
| `进入俯瞰 [CAPSLOCK]` 提示胶囊 | **不透明**，近白 `#FDFCFC`，α ≥ 0.997，方差比 0.002–0.006 |

状态胶囊这一条是**两种独立方法互证**：静态截图配对给出"不透明 ≈ `#2B2929`"，视频回归在强相关下给出同一答案。

### 顺带发现的三件事

1. **探索 HUD ↔ 战斗 HUD 在 t≈4.5s 整块切换**（两套完整布局，一套语汇）。
2. **暗屏里有一个近白不透明元件**——`进入俯瞰` 胶囊。所以语域属于**元件**，不属于屏幕；最亮的那一个元件就是此刻唯一的焦点。
3. **世界自带信号黄**——野地里铺满黄色野花（`#FFCD57`）。UI 的黄不是外来的。
