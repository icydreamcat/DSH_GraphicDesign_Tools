# 规则 · 深色界面的一套完整做法

> **这一份是什么**：从一份实测拆解里提取出的**可执行规则**，按内容归类，只留结论与规则，
> 不含它出自哪里、怎么得来的。
>
> **出处（要看证据与推导过程时读它）**：`docs/终末地设计语言拆解.md`。
> 那份是**案例文献**，保留完整的拆解过程、实测数据、被推翻的说法与置信度——规则来自它，
> 但规则本身不该被埋在里面。

一句话：**两种表面，一个信号色，分层做出深度。**

---

## 一、先定表面

同一套语汇用在两种底上，**不是"深色主题"**，是两种材质各自的印刷逻辑：

| 表面 | 是什么 | 用在哪 |
|---|---|---|
| **炭面** | 深色、界面 | 游戏内 HUD、仪表型界面 |
| **纸面** | 浅色、文档 | 标题页、百科、商店、说明文档 |

**规则：先定表面，再定其他一切。** 色值、线宽、字阶、版式规则**两类之间不通用**——
把纸面的大块色搬进炭面（或反之）是最常见的整片错。

## 二、色彩

### 2.1 三个主色，一条纪律

```
纸  #FFFFFF / #E3E3E3     墨  #191919     信号黄  #FFFA00
```

**黄是信号，不是色块。** 它承担信息负载——数值、状态、激活页签、物的流向。
**它的面积由逻辑决定，不由构图决定。** 仿制时把它当装饰大面积铺，是这一类语言最常见的错。

### 2.2 一个色是一条轴，不是一个值

| 状态 | 值 | 规律 |
|---|---|---|
| 主信号 | `#FFFA00` | |
| 实心填充 | `#FFF000` | |
| 高亮 / 悬停 | `#FFFF21` | |
| 悬停加深 | `#EFE701` | |
| 按下加深 | `#E6DE01` | **越深的值用在越"被按下"的状态上** |
| 主视觉成片 | `#FFF500` / `#FFFC46` / `#FFFC27` | 受插画混色影响略有偏移 |

**规则：亮底上的黄必须换深档。** 同一个黄在深底 15.26:1、在奶油底 **1.07:1**——等于抹除。

### 2.3 三种标记色各司其职，不可互换

| 色 | 值 | 职务 |
|---|---|---|
| 橙 | `#FF7500` / `#DB7722` | **待处理 / 未读 / 新** |
| 红 | `#840000` 系 | **紧急 / 状态徽标** |
| 绿 | `#00FFA2` | 能量 / 正常状态 |
| 洋红 | `#FF1AAC` | 异常 / 侵蚀 |

**黄是唯一的品牌信号色；橙是"待处理"；红是"紧急"。** 三者混用是常见错误。

### 2.4 强调色预算

两个指标必须分开读，**只有一个能做判据**：

- `flatShare` — 未被中断的大面积平涂彩色像素。**它测的是"平涂存活量"，不是设计的强调色面积**
  （一条满幅色带被字标、灰块、辉光打断后，`flatShare` 只有 1.0%）
- **色相簇占比** — 该色相的全部像素，含细线、发光线、小徽标

**判据：大块平涂绝不超过 2%**（实测区间 0–2%，特例 3.1%）；
"看见的颜色"主要是线、发光、小徽标累积到 **3%–5%**。

**警告：在自发光为主的界面上 `flatShare` 会系统性低估**——某战斗屏 `flatShare = 0`
而该屏确实充满黄色，因为黄以发射光存在、边缘柔和、不构成平涂。
**自发光界面上必须同时看色相簇占比。**

### 2.5 色彩架构

- 由**一个色相**带全族，用 ramp 工具建阶梯，**不要手挑 tint**
- 每定一个色值，**同时写下它落在哪个面上**。同一个色在不同层上需要不同的取值——
  "底色归一套、文字归另一套"就是裂缝
- 插画与底要合一，**且在插画上做**（双色调、边缘处理），
  **不能用半透明矩形盖**：矩形跟不上主体轮廓，会变成画面上的一个软边方框
- 架构的检验方法是**去色测试**

## 三、排版

- **使用真实测出的阶梯，不要临时定字号**；每个字号自带行距
- **层级靠字号、字重、位置，永远不靠颜色**——颜色承载的层级最脆，
  单色印刷或色觉差异下立刻消失
- **游戏内界面不使用连续比例阶梯。** 它用**一段很窄的文本带 + 一次大幅跳升的展示层**构成层级
  （实测：正文带相邻比 1.07×，到展示层为 2.27×）
- **不要目测字号**：量墨迹高度反推字号（实测 25px 墨迹 → 字号 ≈28px）
- **行长**：中文 **25–40 字/行**是舒适区；超出是真实取舍，要写下来
- **跟踪要刻意设**：展示字收紧，小型大写与标签放开
- **拉丁等宽 / 无衬线字体默认不覆盖中文**，除非实测过——
  把中文塞进 latn-only 字族会渲染成满屏豆腐块，**而引擎不报任何警告**
- **变量字体的字重不能走字体简写的 weight token**（会被忽略）。
  用错不会得到"正常字重"，会得到**发丝线**——看起来像一个刻意的风格选择，极易误交

---

## 四、图形

- **线宽分表面**：炭面 1px，纸面 2px。**需要强调就加线或换色，不加粗**
- **底纹用方格网 + 45° 斜线 + 斜排线填充块**，模数取画布宽的 **5%–7%**
- **底纹必须局部出现、局部消失**，不能均匀铺满
- **形态跟着物体的性质走**：面板圆角很小或直角，动作按钮可胶囊，点与头像才用正圆。
  不要为了风格统一把圆点画成方块，也不要为了柔和把面板倒圆角
- **图元由生成规则拼装**（矩形 / 圆 / 菱形），角点吸附到方格交点——
  这是它们"像工程符号而不像图标"的原因

### 4.1 记号按功能分两类，不可互换

| 类型 | 特征 | 价值在 | 用法 |
|---|---|---|---|
| **标记** | 径向对称，无轴向 | **位置** | 四个定义矩形，放在角上，不要散落 |
| **指针** | 有头有尾 | **它描述的路径** | 引线、指向 |

## 五、深度与层次

**这一维最容易整个漏掉**：面积、数量、线宽、对比度都是平面上的量，深度不是。

- **定层：底 → 承载面 → 可操作面 → 焦点层，共 3–4 层，每层一种职务。**
  实测四档：近黑底 → `#2B2929` → `#C3C3BF`–`#CDCBCB` → `#FDFCFC`
- **焦点层用反相，不加粗、不放大、不加边框，且一次只留一个。**
  这是全套语言里最便宜、也最容易用滥的手法
- **该不透明就不透明。** 分层不等于半透明；HUD 胶囊实测 α ≥ 0.94。
  需要读的数据不让底透过来
- **靠明度差建立的结构要过一遍灰度检查**：1.144:1 的面板在屏幕上成立，打印与单色下消失

---

## 六、密度

- **元素要多、要淡——但"淡"必须由分层供养。**
  目标：**40 个以上区域，单个最大 ≤15%**
- 平面上撒一百个 6% 的记号是糊；**分到 3–4 个深度层上才读成系统**
- **所以顺序是：先定层，再定密度。** 反过来做不出来

---

## 七、版式

- **阅读型版面用列网格**（并把格线画出来）；**仪表型界面用径向**。不要互换
- **长图版式**：色带分区 → 黑牌字段名 → 三角条目 → 发丝线分隔 → 关键词 → 等宽数值
- **细节必须局部化**：实测同一张主视觉，中部细节 0.079、底部两角 0.010，**相差近 8 倍**。
  均匀铺满的纹理读成"壁纸"，局部出现的纹理读成"制图"

---

## 八、禁止清单

- ❌ 把纸面的大块色搬进炭面（或反之）
- ❌ 同时铺开黄、青、绿、洋红、橙——**它们分属不同表面与不同状态，不是一套配色**
- ❌ 用颜色承载层级
- ❌ 用透明度做层次（分层是遮挡，不是半透明）
- ❌ 为了"元素多"而在平面上撒满淡记号（要先分层）
- ❌ 把 `flatShare = 0` 读成"没有这个颜色"
