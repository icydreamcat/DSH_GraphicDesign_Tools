# 设计参考与方法 · 总纲

本文是这套工具链**所有参考与方法文档的索引与判据**。它回答三个问题：库里有什么、
每份什么时候读、以及**一份文档要满足什么条件才配进库**。

它**不是**设计语言的正文。设计语言在 `终末地-设计语言拆解.md`（54 KB，本文的附属详版），
本文只给它指路。

> **入库判据（这份文件存在的理由）**
>
> 这个库里的每一份都**面向外部**：可以随仓库交给一个陌生人，且不带这台机器的任何痕迹。
> 具体三条，缺一条就不入库——
>
> 1. **总结性，不是日志。** 写当前成立的结论，不写"什么时候跑的、跑了多久、之前错了几轮"。
>    按日志读会因为时间造成误会。
> 2. **不带本地内容。** 不出现当前环境绝对路径、会话 id、缓存体积、运行记录、当前环境环境前提。
>    凡引用素材，只写**作品名或角色名**，不写文件在谁机器上的位置。
> 3. **结论要带来源与置信度。** 实测得来的标实测，从课程读来的标课程，推断的标推断。
>    不标就等于把它们混成同一种可信度，而下游读的人再也分不出来。

## 一、三类，以及各自的入口

| 分类 | 放什么 | 判据 | 入库？ |
|---|---|---|---|
| **参考规格** | 别人的作品是怎样构成的：设计语言、色板、字阶、版式 | 对着**量**的材料，用来推导规格，不是用来直接搬 | ✅ 本文第二节 |
| **方法** | 怎么测量、怎么判断、什么时候不该做 | 回答「下一步做什么、怎么读结果」 | ✅ 本文第三节 |
| **过程记录** | 某一轮做了什么、坏了什么、学到什么 | 回答「我上次是怎么栽的」 | ❌ **不入库**，留在本地 |

**硬边界两条，都是踩过才立的：**

- **项目自己的艺术拆解不进通用库。** 它只对那一个版面成立；搬进通用库会让后来的 agent
  拿别人的结论去套自己的画面——这正是「参数接近、视觉难看」的来源之一。
  泛化得出来的那一份才进 `reference/`。
- **过程记录与本地前提不入库。** 当前环境环境、交付清点、运行状态都属于这一台机器，
  换机器即失效。它们进本地库，不进这里。

## 二、参考规格

### 2.1 主文档：一份工业编辑风的完整拆解

**入库成品**：`终末地-设计语言拆解.md`（54 KB）。

它按**要素**组织，每个值都标来源与置信度，并且含一节「由此被修正的结论」——
把被实物推翻的说法留着作警示，因为一条结论唯一能证明自己来自实测、而不是来自既有印象的
证据，就是它差一点是什么。

骨架（照这个结构读，或照这个结构写下一份）：

```
0  三十秒版本
1  它要解决什么问题（先问功能，再问形式）
2  核心结构：两种表面
3  色彩系统      三主色 + 一条纪律；色的家族是一条轴不是一个值；强调色预算
4  排版系统      展示字族 / 中文 / 两套字阶（网页层与实机层不同）/ 行长
5  形态语言      图形词汇表：母题、底纹、切角、发丝线、标记与指针、图元生成规则
6  版式与网格    实测对照、两种表面的版式规则
7  继承与断裂    与同源作品的实测对照
8  可执行规则    定表面 → 定强调色 → 定字 → 定图形 → 定深度 → 定版式 → 禁止清单
9  证据与置信度  实测清单 / 单帧测量的边界 / 降级为印象的部分 / 会推翻本文的检查
```

**这套语言的三条主干**（读全文之前先记住，否则细节会散）：

1. **两种表面。** 同一套语汇用在两种底上：**炭面**（深色、界面）与**纸面**（浅色、文档）。
   不是「深色主题」，是两种材质各自的印刷逻辑。
2. **黄是信号，不是色块。** 黄色承担信息负载——数值、状态、激活页签、物的流向。
   它的面积由**逻辑**决定，不由构图决定。仿制时把它当装饰大面积铺，是这一类语言最常见的错。
3. **深度靠分层，不靠阴影。** 层级由几层各自的**职务**决定，不是靠投影强弱。

**读法警告**：参考给的是**词汇**，不是**风格**。抄标记不抄语境，会把讲某种植物的图
变成放满数据读数的仪表盘。

### 2.2 附属材料

| 文档 | 是什么 | 什么时候读 |
|---|---|---|
| `prior-设计语言.md` | 同一套语言的**令牌级**整理：中性色亮/暗两套、强调色两套、圆角与等宽数字的纪律 | 要落地成 CSS 变量或组件库时 |
| `prior-明日方舟UI技能.md` | 同源作品的可复用要点 | 做同一体系的东西时 |
| `prior-终末地UI说明.md` | 该作品的界面说明 | 同上 |
| `官方原图提炼的设计原理.md` | 从**官方成图**反推的原理，带逐带明度实测与功能位配色表 | 想知道「官方比我多做了什么」时 |
| `timeline-KV-拆解.md` | 对一张 KV 的实测拆解（明暗、网格、线宽、细节分布） | 要复刻骨架而不是观感时 |

**从官方成图反推出来的两条可执行结论**（这两条比任何观感描述都有用）：

- **整版是一条明度弧，不是一块底。** 实测十带均亮度从顶部 0.117 到最亮带 0.947，
  跨度 0.83，最深处在**顶部**。可执行形式：顶部约一半画面落在中低明度，暗端从顶部开始，
  整版向底部单向变亮，最后约 15% 留作纯净负空间。
- **调色板是功能位，不是一堆颜色。** 近黑是**暖棕黑**、半调的中间调是**暖棕**，不是中性灰——
  中性灰会让整版发冷发脏。

四门合成设计课的拆解（Vol.13 / 纸张合成 / 细节爆表合成 / 如何学明日方舟做设计）
与它们的合并通法：

| 文档 | 是什么 |
|---|---|
| `合成设计方法总纲-四门课合并.md` | **合并后的通法**：判定顺序、从零做一个元素的四条工序链、风格怎么拿捏、质感怎么做 |
| `合成设计课-Vol13拆解.md` | Vol.13 的逐节拆解 |
| `纸张合成课-拆解.md` | 纸张合成的工序 |
| `细节爆表合成课-拆解.md` | 细节密度的做法 |
| `明日方舟设计课-拆解.md` | 排版与版面层的课 |

**这一族的核心不是操作，是判据。** 四门课真正教的是：这些材质原来都可以自己做出来；
要学的是**基础原理与统一的实践方法**，不是把材质一种一种记下来抄。

**证据等级声明（必须随这一族一起读）**：这些内容来自**课程画面与字幕的抽帧判读**，
**音频没有听**。字幕是单句片段，引用前应回看原时间点；正文段落因分辨率不足一律记为
「读不清」，未作任何补全。

## 三、方法

| 文档 | 是什么 | 什么时候读 |
|---|---|---|
| `设计方法原理-给agent.md` | **方法协议**。四层级顺序、深度轴、面积占比陷阱、测量边界。带判据、阈值、失败模式 | **开工前读第 0–3 节**（顺序不可跳）；交付前过检查清单 |
| `设计问题与技术问题-给agent.md` | 交付复盘：每条都是实际犯的错，带数字 | 症状出现时对照找失效模式 |
| `清点先于测量.md` | **CNI 三步**：INVENTORY → QUALIFY → MEASURE，顺序不可跳 | 拿到参考图、准备测之前 |
| `遮罩溶解-只能单块整盒alpha.md` | 一种效果的**唯一正确写法**，以及三种会留下可见缺陷的错法 | 要用这个效果之前 |
| `视频测量-录像要求与工具.md` | 什么必须靠录像判定（透明度、动效），以及怎么录 | 要判定「这一层是不是半透明」时 |
| `引擎需要补的技术-来自四门合成课.md` | 引擎与课程做法的差距清单 | 要加引擎能力之前 |

### 3.1 一条贯穿全部方法的主线：顺序错了，数值再准也没用

`清点先于测量` 记录的这条顺序，是整个方法族的枢轴：

```
① INVENTORY  清点：图上实际有哪些物件 —— 逐个数出来，命名，定类别，记位置。此时不测比例
② QUALIFY    定性：每类物件在这张图里做什么
③ MEASURE    测量：到这一步才取数
```

跳过①直接测，得到的是**数值接近、画面荒谬**：把一个珊瑚色区块、一个白框、一条棋盘带、
几张贴纸合并成一个标量去拟合，等于把「一张桌子、两把椅子、一盏灯」压缩成「家具占比 0.4」——
数字对，家具没了。

### 3.2 测量的方向只有一个

**测量能否证，不能确证。** 比值、占比、色数可以告诉你一页**错了**；
永远不能告诉你一页**对了**。一个指标落在参考区间内，只证明某一种特定缺陷不存在。

配套两条：

- **先确立图上有什么，再测。** 在错误的内容集合上测出的占比，是一个精确回答了的、
  没人问过的问题。
- **不要加一个只影响数字的东西。** 如果一个元素存在的理由是某个指标，它不是设计决定。

### 3.3 改动又小又散，就是在凑参数

同样的症状在多个项目里出现：**每一处局部修正都局部正确，整张图持续变坏。**
判据很简单——改动幅度小、且分散在多个互不相邻的区域，那么无论改了多少版，
结构都没有动过，动的只是数值。

**对策是问一句**：是你声明的哪一项决定错了？如果 `gates` 里没有任何一项错，
那你找到的不是问题，是症状。

## 四、写一份能入库的文档：五条规矩

1. **结论性，不叙事。** 正文不出现「本地发生了什么、做了什么实验、上一版怎么想」。
   写「跨度 0.83」，不写「跑了三次才量对」；写「把截图当平面读，会把合成值当成设计值」，
   不写「我上一版犯了这个错」。**作者的经历不属于文档，结论与判据才属于。**
2. **但不许删掉被否定的说法。** 一条结论唯一能证明自己来自实测的证据，就是它差一点是什么。
   做法是**改语态、不删内容**：

   | 不写 | 写 |
   |---|---|
   | 我上一版假设两者一致，实测否定了 | 「两者一致」不成立，实测已否定 |
   | 我上一版据此写了"几何是径向的" | 据此得出「几何是径向的」——结论对，证据用错了 |
   | 这一层被我遗漏了 | 这一层常被遗漏 |

   错的说法仍然可见（防止别人重犯），作者的经过不再出现。
3. **每个值标来源与置信度。** 实测 / 课程 / 推断，三档。混在一起就等于把推断升格成了事实。
4. **不写当前环境的东西。** 无绝对路径、无会话标识、无缓存体积、无环境前提、无运行时长。
   引素材只写作品名或角色名。
5. **每一段都要能被下游直接用。** 如果一段话读完只让人知道「这里发生过一件事」，
   它对入库没有贡献。

**为什么这值得写进判据**：文档一旦带上经过，读者就无法区分
「实测得到的结论」与「当时的一次判断」——而两者的可信度差一个数量级。

## 五、这份索引不包含什么

- **过程记录**：某一轮做了什么、坏了什么。它们回答的是「我上次怎么栽的」，
  属于本地库，不属于这里。
- **当前环境前提**：环境限制、交付清点、工具调用分布。换机器即失效。
- **项目内部的艺术拆解**：只对那一个版面成立，留在项目里。
- **未验证的推断**：可以写，但必须标【推断】并说清它没被验证过。
