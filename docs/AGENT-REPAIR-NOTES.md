来源：一次完整的 KV 海报制作（2560×1219，明日方舟缪尔赛思 / GINKGO）。
工程：`D:\DSH_GDT\DSH_GraphicDesign_Tools\engine`。成品：`out/muelsyse-ginkgo-kv.png` / `.psd`。
本文只写**有证据的事**：每条都给出当时的现象、根因、修法。
凡是我判断错的，也写进去——错误类型比正确结论更有用。

## 一、引擎真 bug（已修，各带证据）

### 1. `resolveLength` 把负坐标当比例
`src/render.mjs`

```js
// 旧
return value <= 1 ? value * total : value
```

`x: -30` 满足 `<= 1`，被算成 `-30 × 2560 = -76800`，图层画到画布外。
**报告完全干净、无警告。** 同一坑连吞两次（`-179` → `-458240`）。

```js
// 新
return value >= 0 && value <= 1 ? value * total : value
```

**为什么重要**：负偏移是"出血"（bleed）的正常写法，任何超出页边的构图都要用。
**测试点**：`resolveLength(-30, 2560) === -30`；`resolveLength(0.5, 2560) === 1280`。

### 2. `ellipse` 忽略 `paint: 'none'`
`src/render.mjs` 的 `drawLeaf` 分支里，`rect` / `polygon` / `path` 都支持 `paint: 'none'`
表示"只描边"，**只有 `ellipse` 无条件填充**，于是 `parseColor('none')` 抛
`unrecognised colour "none"`，**该层静默消失**。
而"无填充的椭圆满环"正是画发丝细线圆环的唯一方式。

### 3. `proportion.subjectTooLarge` 误判横带
`src/verify.mjs`

```js
if (hFraction > 0.75 || wFraction > 0.75) error(...)   // 旧
if (hFraction > 0.75 && wFraction > 0.75) error(...)   // 新
```

旧判据把**任何宽幅图像**都判成"主体过大"：一条 2560×195 的树冠带、
一条通宽 74% 高的背景铺底都中招。
**区别在于**：主体立绘两个轴都大；背景带只大一个轴。

### 4. 多轴 mask 不 `blend: 'multiply'` 会取并集而非乘积
`drawMask` 的文档里已经写了这条，但**报告不会提示你犯了**：
两个轴向的渐变互不透明地叠加 → 取并集 → 横向渐变盖掉纵向渐变 →
掩版处处为白 → `maskRetained: 1`（即"什么都没遮住"）。
**症状**：立绘是一块硬边矩形，而不是柔和溶解。

### 5. 层序：全幅层会盖住它之前的一切
我把"植物"放在第 08 段（调子板 03、插画 04、网点 05、横尺线 07 之后，
但那时**它们都在植物之上**？不——反过来：**植物在第 08 段时还在它们下面**）。
结果 fit-to-screen **完全看不见**：不是淡，是**不在**。
> "植物是版面的骨架"与"植物在照片后面"不可能同时成立。

**修法不是调不透明度，是改层序。**

### 6. effect 的执行顺序与 mask
`effects` 数组**按顺序**执行，全部跑完才应用 mask。
`halftone` 带 `replace: true` 会**先清空整个缓冲**，所以它只能有一个（否则后者清掉前者）。
`halftone` 的 `tone: 'source'` 读的是**该层自己的像素**——铺在实心 rect 上时读的是填充色，
**不是它下面的画面**，所以"响应图像明暗的网点"必须让 rect 本身极淡或改用 `coverage` 驱动。

## 二、自检失效 —— 本次最值钱的一节

**核心结论：与被测代码共享假设的检查器，测不出任何东西。**
我在同一类错误上栽了**六次**，每次都报告"0 问题"。

| # | 缺陷 | 为什么自检放过了它 |
|---|---|---|
| 1 | `bearing()` 的 `anchorY` **符号写反** | `box.y = cy + a·h − h`，只在 `a = 0.5` 时等于正确的 `cy − a·h`。220px 的叶片偏离接点 **207px** |
| 2 | 审计用 `l.y + l.h * 0.97` 反推接点 | **和代码同一个错约定** → 永远 0 问题 |
| 3 | `bladeAt` 排除表建在递归函数**内部** | 三条枝各自为政，跨枝碰撞看不见 |
| 4 | 排除检查比的是**点距** | 被绘制的实体是**框**，框远大于点 → 独立审计查出 **48 对重叠，最严重 100%** |
| 5 | 覆盖率审计**不读蒙版** | 报"枫叶覆盖页脚 65%"；蒙版早已把它降到 ~8%，**真实 3%** |
| 6 | 框相交 ≠ 像素相交 | L 形素材包围框内大片空白 → 5 处假碰撞 |

### 可直接搬进 agent 的规范

1. **约束必须在"被绘制的几何"上求值。** 不要用一个点代替一个框，不要用半径和代替实际形状。
2. **审计不得重新推导它所检查的约定。** 把约定**记录在数据上**（例如把那层的 `anchorY`
   写进图层对象），审计**读**它，而不是再算一遍。
3. **每个检查项相互独立。** 一个错约定不能连带豁免下游所有检查。
4. **优先选择无需约定的度量。** "两个矩形是否相交"不需要任何约定；
   "两点距离是否小于半径和"需要三个约定（点在哪、半径是什么、和怎么算）。
5. **报告要区分"量出来的"和"期望的"。**
6. **修完要能复现故障。** 我修 `anchorY` 之后没有立刻重跑旧审计看它是否从 0 变成 48 ——
   正是这一步能在当天就暴露问题。

## 三、缺失的工具（我都补了，建议内置）

| 工具 | 为什么必须存在 |
|---|---|
| `text-measure.mjs` | 渲染报告对 `wrap: false` 的单行文本恒返回 `widest: 0`——**标题到底多宽在报告里看不见**。我因此连续三次用估计值排版，三次都溢出到别的元素上 |
| `subject-probe.mjs` | 从成品插画量主体：墨迹轮廓、12 带明度弧、量化调色板、色相簇。没有它，"主体在哪"只能目测 |
| `icon-inventory.mjs` | 图标包盘点：尺寸、alpha 模式（cutout/partial/opaque）、墨迹占比；`--sheet` 出接触印相表。**只有排出印相表才知道形是什么** |
| `recolor-icon.mjs` | 把黑剪影改写成页面墨色。引擎做不到的原因：`tint` 用 multiply，**黑 × 橄榄还是黑** |
| `font-specimen.mjs` | 31 个已注册字体的样张。**只有排出来才发现大部分字体渲染不了中文**（豆腐块/问号） |
| `font-try.mjs` | 候选面按**本页真实文字**在三个字号上排出来 + 量宽。这是选字的唯一依据 |
| `crop-view.mjs`（已有） | **1:1 裁切**。缩略图会骗人；本次几乎每个真问题都是靠它发现的 |
| `prep-maple.mjs` | 素材照片预处理：裁水印、抠底、双色调重映射、镜像、裁到墨迹框 |
| `audit-image-over-type.mjs` | 图片**实际墨迹**（含蒙版加权）覆盖文字的比例 |
| `audit-plant.mjs` | 连通性 + 重叠 + 分布（网格占用、聚集系数） |

### 修复类工具（因为我自己砸了四次文件）
`fix-source-encoding.mjs`｜`fix-cjk-strings.mjs`｜`fix-line.mjs`｜`fix-swallowed-code.mjs`

其中 `fix-swallowed-code.mjs` 识别一个具体的**故障签名**：
**一行以 `//` 开头但里面含有语句**。编码损坏把多字节分隔符撑开，
把下一行的 `layers.push({ id: '15-detail' ... })` 吞进了注释 —— 该组**从未执行**，
`detail` 数组被构建后丢弃，**报告干净**（44 层 → 修后 73 层）。

## 四、设计思维（判断，不是规则）

1. **参考图的语汇是它的主题，不是可照搬的风格。** 它的标记是仪表，
   因为**它那一页本身就是一份虚构的企业档案**。抄标记不抄语境，
   等于往一张讲银杏的图上放数据读数。
2. **同一份素材在不同语境下读作不同东西。** 环就是环、扇就是扇——
   参考图里是仪表，这里可以是枝叶。**命名诚实即可，不必换文件。**
3. **一条生成规则胜过一百次摆放。** 我在没有规则时得到的是一页
   "排得很整齐的陌生人"：每个元素都独立好看，彼此不回答。
4. **材质要"画"或"改造"，不能"贴"。** 复制出来的形没有解剖结构，旋转变不出来。
5. **但真实素材优于生成的几何——前提是它是对的题材。** 照片自带的遮挡、交叠、
   细枝层次，我用递归几何做了十轮也没做出来。
6. **照片是"块面"，不是"纹理"。** 字要落在它让出的空处，而不是压在它上面。
7. **标记有功能之分，不可互换：**
   - **标记性**：径向对称、无轴向 → 价值在**位置**。四枚定义一个矩形，
     眼睛会把框住的范围读成一个整体。**放四角，不是撒开。**
   - **指向性**：有头有尾 → 价值在**它描述的路径**。
8. **差异本身就是机制，不是点缀。** 一页同款同浓的十字是**纹理，纹理没有方向**。
   要沿视线递变：**用哪款、用几枚、多浓**三个维度同时变。
9. **层级要压住。** 标记不能抢——组不透明度 + 尺寸比（最大的标记 32px 对字标 218px，1:7）。
10. **两幅图要共享一道工艺**，否则读作"一张印刷品加一张贴图"。
11. **字可以是材质**（放大的描边字标横跨全页），不只是标签。
12. **换素材必须同时删旧素材。** 只加不删会让两代设计同时出现在版面上，
    而旧的那代往往正是上一轮被否掉的做法。

## 五、执行规范（我违反过的，逐条写清代价）

### 1. 永远不要用 shell 改源码 —— 我犯了四次
```powershell
# 危险：Get-Content -Raw | Set-Content 会把 UTF-8 按系统 ANSI 编解码
(Get-Content $f -Raw) -replace 'a','b' | Set-Content $f
```
**后果**：中文全部变乱码（`缪尔赛思` → `缂皵璧涙€?`），长破折号丢字节且**不可逆**；
更隐蔽的是**多字节字符撑开分隔符、把下一行代码吞进 `//` 注释**，
于是那行永不执行而报告全绿。

**规范**：
- 改源码用**编辑工具**，不用 shell。
- 需要脚本时**写成文件再跑**，不要 `node -e`（shell 引号会二次损坏脚本本身）。
- 文件损坏时：先跑 `fix-source-encoding.mjs`，再用 `fix-line.mjs` **按行号**修
  （损坏文本含 U+FFFD，字面匹配必然失败）。

### 2. 先量，再改
本次的失败清单里，**大部分**是我用"看起来对"代替"量出来"：
字宽估过三次、内阴影强度估过一次（1:1 裁切证明根本看不见）、
植物几何估过两次、环场参数估过三次。

### 3. 每次判断都在 1:1 裁切上复核
缩略图骗了我至少四次。真实问题几乎都是裁切图发现的：
短枝渲染成"苍白绷带"、叶脉超出叶缘、字砖被做旧层洗淡。

### 4. 加与删在同一次改动里完成
见四.12。

### 5. 交付时给出：改哪个文件、哪个指标应该动、怎么回滚
本次每次迭代都给了：`0 error / 0 warning`、PSD 审计 PASS、42/42 自检、
峰值细节 0.062–0.064（参考 0.061）、焦点唯一、以及具体的重叠对数／覆盖率。

### 6. 无法验证的事要明说
本机 Photoshop 无法启动（见 `HANDOVER.md` §2），所以那份 PSD
**没有在 Photoshop 里真正打开过**——结构与通道流是独立解析器验的，不是 PS 验的。
这类话必须写，否则"验证过"会被误读。

## 六、建议写进 agent 指令的三句话

1. **约束在被绘制的几何上求值；审计不得重新推导它所检查的约定。**
2. **改源码用编辑工具；需要脚本就写成文件。shell 会静默毁掉非 ASCII。**
3. **替换素材时，加法与减法在同一次改动里完成。**
