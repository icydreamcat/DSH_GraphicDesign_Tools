# 遥 · 平面设计任务书（设计前写定，先于任何元素）

## 0. 素材实测（不是估计）

`assets/haruka-raw.png`，1352×1352，**带 alpha 的透明立绘**（实测：不透明 30.1%，
全透明 64.3%，半透明 5.6%）。所以「地面」由我决定，不是被素材绑定的。

连通域分析（`tools/isolate-subject.mjs`）实测：

| 连通域 | 面积 | 位置（画布占比） | 说明 |
|---|---|---|---|
| #0 | 618 261 px | x0.177 y0.007 w0.689 h0.987 | **主体**（含法杖、飘带） |
| #1 | 3 101 px | x0.604 y0.496 w0.040 h0.058 | 大泡 |
| #2 | 2 836 px | x0.190 y0.275 w0.044 h0.047 | 大泡 |
| 其余 | ≤1 042 px ×23 | — | 小泡、碎屑 |

主体是**单一连通域**，占 68.9% 宽、98.7% 高。逐行占用率（12×16 网格）显示：
**左缘 x≈0.18，右缘在 y0.56 一线扩到 x≈0.87**（白色飘带甩出）。
y>0.87 的裙摆/靴区只占 x0.20→0.60 —— 这决定了文字能放在哪。

关键约束（后面全部结论由它推出）：

- 图形**天然接近满高**，画面里没有「顶部留白」这种东西可用；
- 左侧下方 y0.875→0.95 的 x<0.20 是**唯一干净的大块空场**；
- y0.56 起右侧 x>0.87 被飘带占住，右侧竖栏在最宽处会被压到约 250px。

## 1. 功能（这份东西要完成什么）

角色宣发主视觉（KV）。**三秒之内**读者必须拿到两件事：
**这是「遥」**，以及**她是六星护佑者**。
图已经很满、很好看，设计的职责不是把它变好看，是**让「她是谁」在图上成立**。

## 2. 层级与阅读路径

| 顺位 | 元素 | 凭什么 |
|---|---|---|
| 一 | **遥**（340px 中文，深绯） | 全画面唯一的大字号。比下一级大 7.2 倍。 |
| 二 | 面部（图内，y≈0.16） | 视线入口。**面上不加任何文字**，让脸保持干净。 |
| 三 | HARUKA / 护佑者 6★ | 名字的注脚，同一簇内。 |
| 四 | 底栏技术信息（天赋·技能·势力） | 需要时读，不需要时是肌理。 |
| 五 | 网格、刻度、网点、缩微标记 | 只被感觉，不被看见。 |

**眼睛的路径**：脸 → 沿身体下行 → 左下角**遥** → 名字下方注脚 → 沿底边横栏右行读完。
这是设计好的下行路径，不是巧合：名字压在**图的重量已经结束**的地方。

**让位的东西**：底栏全部信息、所有技术线、所有缩微标记——它们的使命是可读但不抢。

## 3. 关系（比例，不是尺寸）

- 画布 2400×3394（A4 300dpi）。**模数 20px = 1 格**，120 格宽。
  页边 10 格 = 200px。**所有坐标取 20 的整数倍**——可核对，不是凑出来的。
- 主体：放大 1.249×，占画布**高 62%**（实测带高 1689px ÷ 3394）。落在 50–65% 带内。
- **遥 340px = 底栏正文 15px 的 22.7 倍**；= 画布高的 10%。
- 强调色预算：深绯只用于名字、少数标签、几条线 ≈ 画面 **2–4% 的平涂占比**。

## 4. 形式

暖纸地 `#F2EFE9`（**不是纯白**，纯白是屏幕，暖白是纸）；
墨色 `#22232B`（带蓝的近黑，**不是 #000**）；
主强调 **深绯 `#9E2B22`**——取自角色发色与法杖，是她的颜色；
次强调 **靛 `#2F3E6B`**——取自她的深蓝裙；
技术灰 `#76736D`（对纸 4.1:1，可读但仍远低于名字的对比）。

半调网点**只出现在左侧一侧并向右、向下淡出**（参考语言实测：网点是局部事件，
不是均匀铺满）。底纹与渐变服从同一条纪律。

# 交付记录（设计完成后回填，全部为实测）

> **注意：本文件记录的是 v1（旧稿）。v12 已按官方原图重做，
> 原理与实测见 `scenes/official-principles.md`，成品为
> `out/haruka-kv-v12.png` / `out/haruka-kv-v12.psd`。**
> 旧稿的核心问题就一句话：**纸白占比 85.8%、暗部 0.4%**，而官方是
> 纸白 31.2%、暗部 26.7%。三分之二是空纸，所以"空、平、单薄"。

**最终形态**：2400 × 3394（A4 300dpi 竖版），330 个元素、24 个顶层图层。

| 检验项 | 结果 | 来源 |
|---|---|---|
| 栅格 | 列距 330px / 行距 165px，强度 0.829 | `design_critique` |
| **焦点唯一** | **是 —— 0 个竞争区域** | `design_critique` |
| 版面自带气质 | 是（有栅格、笔画统一 1px 占 49%、调子带受控） | `design_critique` |
| 调子带 | 0.619（受控），均亮度 0.877 | `design_verify` |
| 主体占比 | 画布高 49.8% | 渲染报告 |
| 局部细节 | 峰值 0.060，均值 0.018，**50% 的格**有真实细节 | `design_verify` |
| 字号层级 | 主/次 = 6.667× | `design_verify` |
| 溢出 / 字体回退 | **0** | 渲染报告 |

**修掉的四个真实缺陷**（每一个都是渲染后才看得见的）：

1. 行网格按 `M + n * MODULE` 写，底栏横线落到 y=3680（画布只有 3394）——**画外**。
   改为由页边与模数推导的 `row()`，并写了 `tools/read-report.mjs` 专门抓"画出画布"。
2. 文字按**框顶**定位，而渲染器的首行基线是 `y + size*0.82`——340px 的字实际低
   279px，遥 / HARUKA / 职阶三行叠在一起。改为按基线定位（`blk()` 反解渲染器规则）。
3. **网点一个都没画出来**：`replace: true` 会把整个 RGBA 缓冲清零（连 alpha 一起），
   半调的 `sourceInk` 门随后跳过每一个像素，实测 `{dots: 0, coverage: 0}`——
   而渲染报告里其他每一行都正常。已在 `src/tone.mjs` 修正（清零前先取形状覆盖），
   实测 13243 点 / coverage 0.108。
4. **多行文字叠成一行**：`font.lineHeight` 是 **em 倍数**而不是画布比例，
   写 `0.0066` 等于 0.09px 行距，两行 14px 直接压在一起。
   `tools/line-probe.mjs` 用像素行带数验证：不写 lineHeight 时是两条独立行带、20px 行距。
   ——这条**只在 1:1 裁切里看得见**，44% 缩略图完全正常，所以有了 `tools/crop-view.mjs`。

**还有一个 1:1 才暴露的缺陷**：罗马数字标记方块与 HARUKA 的基线撞在一起。
44% 缩略图里看不见，900px 裁切里一目了然。已移到右侧中部空场。

**我自己认为最弱的一处**：中部偏右（约 x 1300–2100、y 1300–2900）仍是一大片空场。
我放了一个标注引线（`ORIGINIUM ARTS / 施术单元`）去补局部的细节峰值，它确实
把该处从 0.003 抬了起来，但**标注本身在视觉上略孤立**——它离法杖比理想的远一点。
这是"减法优先"与"局部细节要有落点"之间的取舍，我选了后者。若客户认为这片空场
是缺陷，正确的下一步是**整体重新裁切画布**（减少右侧留白）而不是再往上加元素。


## 5. 已知风险（设计前写下，交付时逐条核对）

1. 白衣亮度 ≈ 0.95，纸地 ≈ 0.87 → 对比仅 1.1:1，**白衣可能糊进纸里**。
   → **已处理并核对**：图形上一条曲线把高光压到 ≈0.91、黑场抬到 12。
   1:1 目视确认：右袖与下摆白纱的轮廓线（画师自己画的冷灰阴影）足以立住形体，
   白衣"浮在纸上"但**没有消失**，这正是想要的效果——她从纸里长出来，不是贴上去。
2. 若**遥**与裙摆重叠过多，名字的识别性下降。
   → **未发生**：实测字形框 x 0.088–0.167、y 0.735–0.835，而主体墨迹 x≥0.177 才起，
   所以名字 100% 落在净空纸上，只有右下角压到淡绯色飘带，那处没有细节可争。
3. 底栏若与靴子打架。
   → **未发生**：图形墨迹止于 y 2277，底栏横线在 y 2993，中间 716px 全空。
