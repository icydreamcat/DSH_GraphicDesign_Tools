## 0. 这个文件解决的根本问题

最后一轮评审说的是对的，而且是最根本的一条：

> **"整张图里的所有内容并没有构成实际的关联和节奏，而你的复杂，是数量上的复杂，
> 不是多样性，不是层级，不是结构性，整张图一开始就需要一个逻辑方向把所有内容串在一起。"**

原因很具体：**之前没有任何生成规则。** 页面上的每个标记都是我在模数坐标上
一个一个摆的，因为"放在那里好看"。这样摆出来的东西之间不可能有关系——
**没有任何一个元素的位置是由另一个元素决定的**。
于是得到一页"排得很整齐的陌生人"：卡片一列、五联框一行、环场一堆、底条一排，
彼此不回答。

**所以重写，而不是继续改。**

## 1. 唯一的规则

> **全页只有一株植物。** 主干从左页边出血进入，横穿整张画布。
> 所有标记都是这株植物的节或着生叶，**深度决定大小、粗细、浓淡**。
> 左版的信息是这株植物的**标注**，不是另一个结构。

一个递归生长器决定一切：节点画一段**曲线茎**，在茎上按深度放一个着生叶，
然后以极坐标分成两个子枝。位置、尺度、线宽、不透明度、承载哪种叶——
**全部由深度和父节点的末端推出**。文件里没有任何手工摆放的标记。

层级来自**一个数**：`shrink^depth`。根部附近的一片叶比末梢的重，
不是因为有人挑了两个尺寸，而是因为这个指数。

四个细节各自都是踩过坑之后定的：

| 细节 | 为什么 |
|---|---|
| **曲线茎**（二次贝塞尔 + 交替侧向弓度）| 直线段在递归角度下读作**脚手架**或分形演示——1:1 裁切里就是几根长直杆横在版面上 |
| **逐级累积转向** | 让茎**横穿**页面而不是之字形抖动 |
| **叶按深度循环** | 层次变化而不增加物件的种类 |
| **确定性 hash 抖动** | 两次渲染逐字节可比；改数字就一定是改了设计 |

**主干参数是量出来的，不是猜的**：第一次"一株植物"失败在**几何**上——
左肢根在 `(-40, 946)`、角度 `-76°`（几乎垂直向上），于是它沿左页边爬到 `x=11`，
**"横穿页面"的主干根本不存在**。根角改成 `-17°` 之后才真的跨过整张画布。
同一段里 `turn` 从 `-5` 降到 `-2`：累加到深度 6 时 -30° 会让主干拐弯向上爬成竖直弧。

## 2. 层序（整个版面按这个顺序搭）

```
01-07  图画     ground / ghost / 调子板 / plate / 网点 / 纸缝 / 横尺线
08     植物     一根主干 + 两条下木，共 201 段茎、201 片着生叶
09-11  标记、字标、标注
13-14  做旧颗粒 + 收尾曲线   ← 必须在墨之前
15     植物与框、砖，压在做过旧的纸上
```

**一条踩过两次的坑**：第一版重写把植物放在第 08 段生成，结果 fit-to-screen
**完全看不见**——不是淡，是不在。原因是层序：第 08 段时它还在左版调子板、
插画、网点、横尺线**下面**。"植物是版面的骨架"和"植物在照片后面"不可能同时成立。
**改层序不是改不透明度能解决的问题**，这一点值得记住。

颗粒与收尾曲线必须在墨之前跑完：否则 1:1 裁切里一块实心橄榄字砖会渲染成
一块发灰的矩形、字读不出。**参考图的层序本来就是这样**（做旧 14 层、标点 13 层）：
纸会泛黄，墨不会。

## 3. 语汇：植物，不是仪表

参考图的标记是聚焦芯片、四角括号、点阵、`N° E` 坐标、电平柱——**因为那一页本身
就是一份虚构的企业档案，科学语汇就是它的主题**。把它当风格照搬，等于往一张讲
银杏、落叶、水的图上放数据读数。

现用语汇：`LEAF` 银杏扇 / `FLOWER` 玫瑰窗 / `PETAL` 新月 / `BLADE` 透镜 /
`RIPPLE` 同心环 / `SEED` 菱形 / `NEEDLE` 尖叶。
**同一个文件在参考图里读作仪表、在这里读作枝叶**——环就是环，扇就是扇。
删除的（改名救不回来的）：全部坐标对、段号、电平柱、准星、靶环。

## 4. 效果：只有四个，各有理由

`src/render.mjs` 为此页新增了 `emboss` / `innerShadow` / `glow`
（原先只有 blur/grain/halftone/duotone/toneWipe/shadow/outline，
所以每个标记都是平墨压平纸，整页读作"贴上去的"）。
**每个都先在 `out/fx-probe.png` 里单独验证过才进版面**——"加了效果"和"效果对"是两件事。

| 处理 | 用在哪 | 为什么 |
|---|---|---|
| `engraved` 白微光 + 微浮雕 | 叶片、花头 | **标本图版**：顶部有光，墨略凸于纸。半径 2、强度 0.3——**弱**，40px 标记上给强浮雕会变气泡字 |
| `keyline` `outline` + `keepFill:false` | 大部分叶 | **同一个文件变成自己的细线轮廓**，一个形两种读法 |
| `specimen` 纸白晕 + 投影 | 需要从杂乱底子分离的叶 | 像压在纸上浮起一毫米的标本 |
| `inset` 内阴影 + 浮雕 | **全页唯一一处**：主标记 | 只有它**压进纸里**，所以纸缝压过去读作折痕而不是贴纸上的条纹 |

`inset` 初版 blur 11 / offset 4 / opacity 0.5，1:1 裁切**根本看不见**；
改成 blur 9 / offset 6 / **0.72** 才有冲压感。**量出来的。**

## 8. 叶片是画出来的，不是拼贴的

最后一轮批评：**"叶子是先前素材直接拼接，没有逻辑，不自然，而且依旧是数量堆叠，
没有层次和方向性，你可以手动重绘叶片。"**

这条对，而且指出我在新一轮里犯了同一个错：`growPlant` 换个形状照样是
**"一份素材复制 N 份"**——从圆点换成叶片，本质没变。**复制出来的形没有解剖结构，
旋转也变不出来。**

所以新增 `tools/make-leaf.mjs`，按银杏叶的真实结构生成几何：

| 特征 | 编码方式 |
|---|---|
| **扇形**（宽大于高）| 叶缘由"离中轴的角度"参数化，半径 `1.18·sin^0.5` —— **半径先快后平**，所以是扇不是圆 |
| **中央裂口**（最关键、通用叶形都缺）| 中轴附近按角度切一个方肩凹口，深度 0.10–0.20、宽度 4.5–7.5° |
| **两瓣不等** | `bias` 让一侧饱满 |
| **二叉分脉**（银杏第二个识别特征）| 11 条脉从基部放射，各自在 45% 处**分一次 Y** |
| **叶柄** | 从叶基延伸**到画框下缘**，所以调用方按"基部"挂载就能与枝接上 |
| **波状叶缘** | 边缘加 1.4% 的正弦扰动 |

输出 **6 个变体 × 2 个版**：`leaf-N.png`（叶身剪影）与 `leaf-N-veins.png`（只有叶脉）。
**叶脉是独立图层**，可以用自己的墨色和效果——一份图纸出三种读法（叶、脉、纯轮廓）。

几何写错过两次，都记下来：

1. 第一版按"沿 spread 的分数"参数化叶缘，**裂口因此跑到叶片侧面**（1:1 印相表里
   是一块右边被咬了一口的团）。改成**按离中轴的角度**寻址，裂口就自然是"接近 a=0"。
2. 开裂口 0.20–0.36 时**叶片裂成两瓣肾形**。真实裂口是浅 V，降到 0.10–0.20。
   同时开角从 58–70° 收到 52–60°，因为银杏**宽大于高**。
3. 画框按 `bladeScale 0.72` 硬定，顶点算出来是**负值**，叶子被平切。
   改成**按几何实际范围解出缩放**。
4. 叶柄固定 0.30–0.50 比例时渲染成**叶下一小截孤立的点**，改成自适应到画框下缘。

### 挂载：方向来自叶柄

叶柄以 **55–85° 朝枝梢方向**离开茎，叶片沿叶柄朝向——**每一片叶都在说明枝条往哪长**。
叶片以**叶基（画框高度的 80%）**与茎相接，不是叶心；`bearing()` 因此新增 `anchorY`。

**层级靠数量比**：所有节点挂叶，只有**最深一层**、且**每 5 个取 1 个**才挂花果种子
（上一版是每 3 个取 1 个，导致花头数量压过叶子，等于把装饰标记又请回主导位）。

最终：**252 片绘制叶片**（含叶脉版）对 56 个末梢花果事件、19 处旧素材。

**实测**：0 error / 0 warning；PSD 审计 PASS；引擎自检 42/42；
峰值细节 0.061（参考 0.061）；焦点唯一 0.702。

### 仍未做的

- 右下（字标 + 主标记 + 环）**还没长在植物上**，仍是独立图形。要让"一条逻辑串起全部"，
  下一步是把主标记接成这株植物的**果实/末梢**。

## 9. 加新素材时必须删旧素材

用户的批评：**"你修改之前没有删除之前多余的素材。"**

这条对。上一轮我只做了加法：新画了叶片、接进版面，**旧素材一个没删**。
结果是两代枝叶叠在同一个版面上——其中一代还是"一份素材复制 N 份"，
正是上一轮被指出的那个错。

### 做法：先审计，再删

用一段脚本把 `scenes/muelsyse-ginkgo.json` 里每个 `src` 收出来，
与 `assets/` 下的实际文件对差集：

```
引用中: 19 个文件      孤儿: 13 个图标 + 旧 ginkgo-fan 的 19 处引用
```

**删掉的 14 个文件**（都是这张图早前版本用过、现在不再引用的）：

`arc-pair` `crosshair` `dots3` `dots4` `leaf-disc` `pixel-cross` `pixel-stair`
`rings` `seed` `sun` `target` `umbrella` `fan-line` `ginkgo-fan`

它们分别属于已被替换的：卡片的仪表语汇、同心环场、五联模块行、底部仪表条。

**顺带清掉的死代码**：`RIPPLE` 常量指向已删除的 `rings.png`（悬空引用）、
`LEAF` 常量在植物 `marks` 数组里的 3 处调用、`withoutLibraryFan()` 过滤器
（先过滤再删文件，过滤器本身也成了多余的）。

**没有删的**：`assets/haruka-raw.png`、`haruka-figure.png`、`yao-cutout.png`
——审计显示它们属于**别的场景**（`build-haruka-kv.mjs`、`build-kv.mjs`），
不是我这次留下的，删了会破坏那两个工程。

### 最终清点

```
assets/icons   17 个文件   全部被引用，0 孤儿
assets/leaves  12 个源文件（生成 icons 里那 12 个绘制叶片的来源）
场景引用        18 个素材文件
```

`ginkgo-fan.png` 的引用数：**19 → 0**。

**实测**：渲染报告 0 error / 0 warning；PSD 审计 PASS；引擎自检 42/42；
峰值细节 0.062；焦点唯一 0.702；581 层。

### 这一轮真正的教训

前几轮的教训是"**先量，再改**"。这一轮是它的另一半：

> **替换素材时，加法与减法必须在同一次改动里完成。**
> 只加不删会让两代设计同时出现在版面上，而且旧的往往正是上一轮被否掉的那种做法——
> 于是"已经修好了"和"还没修"会在同一张图上同时成立。
